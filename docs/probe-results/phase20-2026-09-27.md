## VU5（ごみ箱の確認ダイアログが前面に出るか）

fsops の事前確認（fsops §12.2）は、ごみ箱の最大サイズを超える項目を計画の時点で `KindTrashUnavailable` にするので、tana の通常の操作ではダイアログは出ない。
そこで、事前確認を飛ばしてごみ箱へ入れる fsops のテスト `TestTrashPreDeleteAbortHelper`（`FSOPS_TRASH_HELPER_PATH`）を、端末の中で動かした。
fsops の `IFileOperation` の呼び出しはプロセスの中で行われるので、ダイアログを出すのは tana と同じくコンソールのプロセスになる。

手順（`%USERPROFILE%\tana-probe\p20` の `vu5-run.cmd`）:

1. `R:\tana-vu5\big.bin`（2,097,152 バイト。最大サイズ 1 MB を超える）を作る。
2. `fsops.test.exe "-test.run=^TestTrashPreDeleteAbortHelper$" -test.v` を、`FSOPS_TRASH_HELPER_PATH=R:\tana-vu5\big.bin` で動かす。
3. 端末は `prlctl exec --current-user` から `start "" wt.exe ...`（`vu5-wt.cmd`）と `start "" conhost.exe ...`（`vu5-conhost.cmd`）で開いた。
4. 約 12 秒後に `prlctl capture` で画面を撮った。
5. ダイアログの「はい」は押さず、`taskkill /im fsops.test.exe /f` でプロセスを終わらせた。

| 端末 | ダイアログ | 前面に出たか | 終わらせた後の big.bin |
|---|---|---|---|
| Windows Terminal | 「ファイルの削除」「このファイルは大きすぎてごみ箱へ移動できません　完全に削除しますか?」（はい・いいえ） | 出た（端末の窓の上、画面の中央） | 残った（2,097,152 バイト） |
| conhost | 同上 | 出た（端末の窓の上、画面の中央） | 残った（2,097,152 バイト） |

- ダイアログが出ている間、テストの出力は `=== RUN   TestTrashPreDeleteAbortHelper` のまま止まっていた（`Execute` は止まる。fsops §12.2）。
- プロセスを終わらせると、ダイアログも閉じ、ファイルは消えなかった（黙って完全削除にならない。fsops I5）。
- 注意: 端末は自動で開いたので、ダイアログが出る直前に、利用者がその端末でキーを押してはいない。
  tana の実際の操作（端末で Enter を押した直後にごみ箱へ入れる）と同じ状況は、フェーズ21の手動の確認で確かめる。
