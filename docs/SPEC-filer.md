# tana 仕様書（ファイラー本体）

たたき台（2026-09-24）。§15 の未決事項を決めてから確定する。

ファイル操作の仕様は `docs/SPEC-fsops.md` に書く。本書ではその節を「fsops §n」と書く。
fsops の不変条件（fsops §2）は、本書のどの部分よりも優先する。

---

## 1. 目的と範囲

tana は Windows と macOS で動くターミナルのファイラーである。キーボードだけで、フォルダの内容を見て、ファイルを操作する。

ファイル操作の安全性は fsops が保証する（I1〜I7）。UI の役割は次の 3 つである。

- fsops の計画と結果を正確に見せる。
- 利用者の決定をそのまま fsops に渡す。
- 利用者を迷わせない。

最初の版（v0.1）は、fsops を実際の画面から使えることを確かめるための最小限の版とする。v0.1 で扱うのは次のとおり。

- 2 つのペインによるフォルダの閲覧（移動、マーク、隠しファイルの表示切り替え、再読み込み、パスを入力して移動）
- ファイルを関連付けで開く
- コピー・移動・ごみ箱・完全削除・名前の変更・新しいフォルダ
- 確認、衝突の決定、進捗とキャンセル、結果の表示

それ以外は §14 に挙げる。

## 2. UI の原則

fsops の不変条件を UI の側で崩さないための約束。どの画面でも守る。

- **U1 上書き・マージを利用者に代わって決めない**
  衝突の決定の既定は「未選択」とする（fsops の `DecisionUnset`。スキップとして扱われる）。
  上書き・マージを設定するのは、利用者がその衝突で選んだ場合と、「すべてに適用」を選んだ場合だけ。
  例外として、自分自身への衝突（`Conflict.Self`。同じフォルダへのコピー）では、最初から自動リネームを選んでおく。既存のものを置き換えないため。

- **U2 完全削除は専用の確認を経た場合だけ**
  `OpDelete` は、§8.6 の確認画面で `y` を押した場合だけ実行する。
  ごみ箱に入らない項目を、UI が自動で完全削除に切り替えることはしない（fsops I5 の UI 側）。

- **U3 結果を隠さない**
  完了以外の項目があれば、必ず結果画面を出す。警告だけの場合も、メッセージ行で知らせて、あとから見られるようにする（§8.5）。
  「移動元を残した」（`OutcomeCopiedSourceKept`）では、データが無事であることと、残したパスを示す。

- **U4 パスは列挙で得た名前から作る**
  fsops に渡すパスは、フォルダの列挙で得た名前（バイト列）をそのまま使って作る。
  表示用に加工した文字列（制御文字の置き換え、切り詰め、正規化をしたもの）からパスを作ってはいけない。

- **U5 UI を止めない**
  フォルダの列挙・計画・実行は、UI のイベントループとは別の goroutine で行う。時間がかかる処理は途中で中止できるようにする。
  例外は、Windows でごみ箱の確認ダイアログが出た場合（fsops §12.2）。扱いは §8.4 に書く。

- **U6 ファイル名に端末を操作させない**
  制御文字（ESC など）や双方向の制御文字を含む名前を、そのまま端末に出力しない（§9.3）。

## 3. 対象環境

- Windows 10 / 11 では、Windows Terminal を主な対象とする。従来のコンソール（conhost）を対象にするかは §15 で決める。
- macOS では、Terminal.app を主な対象とし、iTerm2 でも確認する。
- 端末の大きさは 80 桁 × 24 行以上。これより小さいときは「端末が小さすぎます」とだけ表示する。
- 表示は日本語だけとする（fsopsctl と同じ）。
- Linux については、コンパイルが通ることだけを保証する（fsops §3 と同じ）。

## 4. 構成と依存

```
cmd/tana/            起動、引数、端末の初期化と復元
internal/fsops/      ファイル操作（既存）
internal/listing/    フォルダの列挙、種類・属性の判定、並べ替え（§6）
internal/textfmt/    表示幅、切り詰め、制御文字の置き換え、サイズ・日時の書式（§9）
internal/app/        画面の状態と操作の流れ。TUI フレームワークに依存しない（§10）
internal/tui/        描画とキー入力。TUI フレームワークに依存する部分だけ
```

- `listing`・`textfmt`・`app` は TUI フレームワークを import しない。
- 画面の状態はすべて `app` が持つ。`tui` が行うのは、その状態を描くことと、キー入力を `app` へのメッセージに変えることだけ。
  この境界は `deps_test.go`（fsops と同じ方式）で確かめる。
- fsops の依存の制限（fsops §4）は変えない。
- fsops 以外のパッケージは外部のライブラリを使ってよい。ただし追加するときは、理由を添えて確認する。
- `listing` が fsops の種類の判定と `\\?\` 形式の変換を使えるようにする方法は、§11 の F1 で決める。

## 5. 画面の構成

### 5.1 メイン画面

左右 2 つのペインと、その下の 3 行（状態行・メッセージ行・キーの案内）からなる。

```text
+= C:\Users\hiro\Documents ============++- D:\backup --------------------------+
|  ..                 <DIR>            ||  ..                 <DIR>            |
|  old-docs           <JCT> 2025-03-01 ||  2025               <DIR> 2025-12-28 |
|  projects           <DIR> 09-24 10:40||  写真               <DIR> 08-02 12:00|
| *写真               <DIR> 09-12 09:15||  議事録             <DIR> 09-01 10:00|
| *議事録             <DIR> 09-20 18:02||  archive.zip         2.3G 08-30 19:45|
|  latest             <LNK> 09-22 08:00||  報告書.docx         1.1M 09-20 09:00|
|  data.csv            128M 09-18 14:30||                                      |
|  README.md           3.1K 09-23 22:10||                                      |
|>*報告書.docx         1.2M 09-24 11:19||                                      |
|  見積書_2026~.xlsx    48K 09-10 16:05||                                      |
|                                      ||                                      |
+= 9 項目  マーク 3 ===================++- 5 項目 -----------------------------+
 報告書.docx   1,234,567 バイト   2026-09-24 11:19:05

 c コピー  m 移動  d ごみ箱  D 完全削除  r 名前  n 新しいフォルダ  ? ヘルプ
```

モックの読み方:

- 80 桁の例。行数は端末の高さに合わせる。
- `>` はカーソル行（実際の画面では反転表示）、`*` はマーク、`=` の枠は操作中のペインを表す。
- 枠は ASCII で書いている。罫線文字を使うかは VU2 の結果で決める。

各部分の内容:

- ペインの枠の上にはフォルダのパス、下には項目数とマークの数を出す。パスが長いときは先頭側を切り詰める（§9.2）。
- 各行には、マーク・名前・サイズ・更新日時を出す。名前以外の欄は幅を固定し、残りの幅を名前に使う。
- サイズの欄には、ファイルならサイズ（§9.4）を出す。ファイル以外は種類を示す。
  `<DIR>` はフォルダ、`<JCT>` はジャンクション、`<LNK>` はシンボリックリンク、`<SPC>` は特殊なファイル（fsops §14 の `TypeSpecial`）。
- 状態行には、カーソル行の項目について、名前（入りきらないときは §9.2 で切り詰める）、バイト数、秒までの更新日時を出す。リンクとジャンクションでは、リンク先も出す。
- メッセージ行には、直前の操作の結果の要約やエラー（「このフォルダを開けません: アクセス権がありません」など）を出す。次のキー入力で消す。

### 5.2 ダイアログ

- 確認・進捗・名前の入力などは、メイン画面の中央に重ねて出す。
- 衝突の決定と結果は一覧が長くなるので、画面全体を使う。

## 6. フォルダの一覧（listing）

列挙と種類の判定:

- 列挙ではリンクを辿らない。
- 種類の判定は fsops と同じ方法で行う（fsops §14.1）。Windows ではジャンクションが `os.Lstat` で `ModeIrregular` に見えるため、Go のモードビットだけに頼らない。
- 隠しファイルとして扱うのは次のもの。表示するかどうかは `.` キーで切り替える（既定は §15）。
  - Windows: `FILE_ATTRIBUTE_HIDDEN` が付いたもの
  - macOS: 名前が `.` で始まるものと、`UF_HIDDEN` が付いたもの
- ボリュームのルート以外では、先頭に `..` を出す。

並べ替え:

- 並び順は §15 の案に従う（フォルダ・ジャンクション → リンク → その他、それぞれの中は名前順）。
- リンクは、リンク先を調べずに並べる。リンク先の確認で待たされないようにするため。
- 名前の比較には、並べ替え用に作ったキーを使う。キーは、大文字小文字をそろえ、Unicode を正規化し、数字の並びを数値として比べられるようにしたもの。
- キーは比較にだけ使い、名前そのものは変えない（U4）。

読み込みの失敗と待ち時間:

- 列挙は別の goroutine で行う。
- 0.2 秒を超えたら「読み込み中… n 件」を出す。Esc で中止し、元のフォルダに戻る（U5）。
- フォルダに入れなかったとき（権限がない、消えているなど）は、元のフォルダに留まり、メッセージ行に理由を出す。
- 表示中のフォルダが消えていたときは、存在する祖先のうち最も近いフォルダを表示する。

再読み込み:

- v0.1 で再読み込みするのは、ファイル操作の後（影響するペインだけ）と、`Ctrl+R` を押したときだけ。フォルダの監視による自動の更新は §14 に挙げる。
- 再読み込みの後は、カーソルを同じ名前（バイト単位で一致）の項目に置く。なければ同じ行の位置に置く。
- マークは、再読み込みの後も名前で保つ。
- ファイル操作で完了（`OutcomeDone`）になった項目のマークは外し、それ以外の項目のマークは残す。やり直しやすくするため。

## 7. キー操作

キーの割り当てはすべて仮。系統（あふ・FD 系か vim 系か）は §15 で決める。

| キー | 操作 |
|---|---|
| ↑ ↓（`j` `k`） | カーソルの移動 |
| PgUp PgDn Home End | ページ単位の移動、先頭、末尾 |
| Enter | フォルダに入る。ファイルなら関連付けで開く（macOS は `open`、Windows は `ShellExecute`） |
| Backspace | 親のフォルダへ |
| Tab | 操作するペインの切り替え |
| Space | マークの切り替え（カーソルを 1 行下へ） |
| `a` | すべてマークする・すべて外す |
| `c` | コピー（反対側のペインのフォルダへ） |
| `m` | 移動（反対側のペインのフォルダへ） |
| `d` | ごみ箱へ |
| `D` | 完全削除 |
| `r` | 名前の変更 |
| `n` | 新しいフォルダ |
| `g` | パスを入力して移動（Windows のドライブの切り替えもこれで行う） |
| `=` | 反対側のペインを同じフォルダにする |
| `.` | 隠しファイルの表示の切り替え |
| `Ctrl+R` | 再読み込み |
| `L` | 直前の操作の結果をもう一度見る |
| `?` | ヘルプ |
| `q` | 終了 |

- 操作の対象は、操作中のペインでマークした項目。マークがなければ、カーソル行の項目を対象にする。`..` は対象にしない。
- 左右の矢印キーの役割（ペインの切り替えか、親のフォルダへの移動か）は §15 で決める。
- v0.1 では、ファイル操作の実行中はほかの操作を受け付けない（§8.4）。

## 8. ファイル操作の流れ

### 8.1 共通の流れ

```text
対象を決める -> 計画（NewPlan） -> 確認画面 -> 衝突の決定（衝突があるときだけ）
  -> 実行（Execute） -> 進捗 -> 結果 -> 再読み込み
```

計画:

- 計画は別の goroutine で作る。
- 0.2 秒を超えたら「計画を作成中…（Esc で中止）」を出す。fsops の `NewPlan` は進捗を返さないため、件数は出せない（§11 の F3）。
- `NewPlan` が error を返したとき（リクエスト全体の問題。fsops §6.1）は、メッセージ行に理由を出して終わる。
  例: 反対側のペインのフォルダが消えていたときは「コピー先のフォルダが見つかりません」と出す。

実行前にやめる場合と、時間が空いた場合:

- 実行前（確認画面・衝突の画面）で Esc を押したら、計画を捨てて何もしない。`NewPlan` はファイルシステムを変更しないので、元に戻すものはない。
- 計画を作ってから実行するまでに時間が空いても、UI では何もしない。計画の後に起きた変化は fsops が安全に扱い、結果で報告する（fsops §7.3）。

両方のペインが同じフォルダの場合:

- コピーは、自分自身への衝突になる（自動リネームを選んだ状態で始まる。U1）。
- 移動は、項目ごとに `KindSameFile` になる。

### 8.2 確認画面

```text
+- コピー -------------------------------------------------+
|                                                          |
|  3 項目を D:\backup へコピーします                       |
|  合計 58 ファイル、1.3 GB                                |
|                                                          |
|  ! 衝突 125 件（トップレベル 3 件）                      |
|  ! 空き容量が足りない見込みです（空き 900 MB）           |
|                                                          |
|  Enter 衝突の確認へ   Esc やめる                         |
+----------------------------------------------------------+
```

確認画面に出すもの:

- 項目数、合計のファイル数とバイト数（`Plan.TotalFiles`・`Plan.TotalBytes`）、移動先。
- 次のものがあれば、行の先頭に `!` を付けて示す。
  - 実行されない項目（`Item.Err` がある項目）と、項目ごとの理由（§8.8）。すべての項目が実行されないときは、実行できないので Esc で閉じるだけにする。
  - 衝突の件数。衝突があれば、Enter で衝突の画面へ進む。なければ、Enter で実行する。
  - 警告（`Plan.Warnings`）。空き容量が足りない見込み、フォルダの中を読めなかった、など。警告があっても実行はできる（fsops §6.4）。

ごみ箱の場合:

- 「n 項目をごみ箱に入れます」と出す。
- ごみ箱では fsops が中身を数えない（fsops §6.3）ので、合計は出さない。
- ごみ箱に入らない項目（計画の時点で分かった `KindTrashUnavailable`）には「ごみ箱に入らないため実行しません」と示す。実行の後、§8.6 で完全削除するかを聞く。

その他:

- 完全削除では、この画面ではなく §8.6 の画面を使う。
- 衝突も警告もないときに確認画面を省くかは §15 で決める。

### 8.3 衝突の決定

```text
 衝突の確認   コピー  C:\Users\hiro\Documents -> D:\backup
 衝突 125 件（トップレベル 3 件）  未選択 122 件（未選択はスキップします）
--------------------------------------------------------------------------------
  名前                 コピー元             コピー先             決定
  写真/                フォルダ             フォルダ             未選択
    （内側の衝突 120 件。マージを選ぶと表示します）
  議事録/              フォルダ             フォルダ             マージ
    2026-09-01.md       4.0K 09-01 10:00     4.0K 09-01 10:00    未選択
    2026-09-08.md       5.2K 09-08 10:00 新  4.1K 09-08 09:00    上書き
> 報告書.docx           1.2M 09-24 11:19 新  1.1M 09-20 09:00    上書き
--------------------------------------------------------------------------------
 この行: s スキップ  o 上書き  r 自動リネーム  m マージ
 すべて: S スキップ  O 上書き  N 新しいときだけ上書き  R 自動リネーム  M マージ
 Enter 実行  Esc やめる  Space 展開・折りたたみ  u 未選択だけ表示
```

`新` は更新日時が新しい方を示す。`未選択` は暗く表示する。

一覧の並べ方:

- トップレベルの衝突を計画の順に並べる。
- フォルダ同士の衝突の内側の衝突（`Conflict.Parent` が 0 でないもの）は、親の下に字下げして出す。
- 内側の衝突は、親がマージのときだけ意味を持つ（fsops §6.3）。親がマージでなければ、件数だけを 1 行で出して折りたたむ。
- Space で展開・折りたたみを切り替える。
- 衝突が数百件以上になる場合を想定し、一覧は画面に入る分だけを描く。
- `u` で、未選択の衝突だけを表示する。

1 行ずつの決定（小文字のキー）:

- 各行では、その行で使える決定だけを選べる（fsops §9.1）。
  - ファイル同士: スキップ・上書き・自動リネーム
  - フォルダ同士: スキップ・自動リネーム・マージ
  - 種類が違う場合と、自分自身への衝突: スキップ・自動リネーム
- 使えない決定のキーは暗く表示する。押しても何もせず、メッセージ行に理由を出す。

まとめての決定（大文字のキー）:

- 大文字のキーは、画面に出ているかどうかにかかわらず、その決定が使えるすべての衝突（内側の衝突を含む）に同じ決定を設定する。
- その決定が使えない衝突は変えずに、「n 件は種類が合わないため変更しませんでした」と出す。
- `N`（新しいときだけ上書き）は、ファイル同士の衝突のうち、コピー元の更新日時が新しいものを上書きに、それ以外をスキップにする。比べる更新日時は計画の時点のもの（`SrcInfo`・`DstInfo`）。

実行:

- Enter で、その時点の決定で実行する。
- 未選択の衝突がスキップになることを、ヘッダに常に出しておく（U1）。

### 8.4 進捗とキャンセル

```text
+- コピー中 -----------------------------------------------+
|                                                          |
|  議事録\2026-09-08.md                                    |
|  [##################----------------------]  45%         |
|  ファイル 26 / 58      597 MB / 1.3 GB                   |
|  毎秒 85 MB   残り 約 9 秒   経過 7 秒                   |
|                                                          |
|  Esc 中止                                                |
+----------------------------------------------------------+
```

進捗画面に出すもの:

- 題名には段階（`Progress.Stage`）を出す。段階は、コピー中・移動中・検証中・移動元を削除中・ごみ箱へ移動中・削除中のいずれか。
- 処理中のパス、ファイル数、バイト数、進捗の棒を出す。
- 速度・残り時間・経過時間は UI が計算する。

進捗の受け取り方:

- fsops の `Progress` は `Execute` の goroutine から呼ばれ、すぐに戻る必要がある（fsops §16）。
- UI は最新の値だけを受け取り、描画は UI のイベントループで行う（§10）。

キャンセル:

- Esc を押すと、キャンセルの確認を出す。

```text
+- 中止の確認 -----------------------------------+
|                                                |
|  中止しますか？                                |
|  書きかけのファイルは残りません。              |
|  完了した項目はそのまま残ります。              |
|                                                |
|  y 中止する   n 続ける                         |
+------------------------------------------------+
```

- `y` を押したら ctx をキャンセルし、`Execute` が戻るまで「中止しています…」を出す。戻ったら結果画面を出す。

Windows のごみ箱の確認ダイアログ:

- Windows のごみ箱では、Windows が完全削除の確認ダイアログを出すことがある。その間 `Execute` は止まっていて、ctx では中断できない（fsops §12.2）。
- ごみ箱へ移動中に 3 秒以上進捗が変わらなければ、「Windows の確認ダイアログが開いている可能性があります（ほかのウィンドウを確認してください）」と出す。
- ダイアログが前面に出るかどうかは VU5 で確かめる。

### 8.5 結果

```text
 移動の結果: 一部にエラーがあります   C:\Users\hiro\Documents -> D:\backup
 移動元を残した 1   失敗 1   スキップ 1   完了 1
--------------------------------------------------------------------------------
> 移動元を残した 写真/            移動先は完成。移動元の 2 件を残しました
                   IMG_0012.jpg   コピーの後に変更されたため残しました
                   IMG_0013.jpg   使用中のため残しました
  失敗           data.csv         ほかのアプリが使用中です
  スキップ       報告書.docx      選択によりスキップ
  完了           議事録/          （選択によるスキップ 1 件）
--------------------------------------------------------------------------------
 Space 詳細の展開・折りたたみ   e 英語の詳細（ログ用）   Enter 閉じる
```

結果画面を出す場合と出さない場合:

- `Status` が `StatusCompleted` でないとき、または完了以外の項目があるときは、結果画面を出す。
- すべて完了で警告もないときは、結果画面は出さない。メッセージ行に「3 項目をコピーしました」などと出す。
- すべて完了で、警告（`ItemResult.Warnings`。メタデータを引き継げなかった、など）だけがあるときも、結果画面は出さない。メッセージ行に「3 項目をコピーしました。一部の属性を引き継げませんでした（L で詳細）」と出す。
  exFAT などへのコピーでは、多くのファイルで `KindMetadata` の警告が出うる（fsops の V6）。そのたびに画面を出すと煩わしいため。
- `L` キーで、直前の操作の結果画面をもう一度出せる。

一覧の並べ方と表示:

- 問題のあるもの（移動元を残した・失敗・一部だけ）を先に並べ、次にスキップ、最後に完了を並べる。同じ区分の中は計画の順。
- 各項目の結果（Outcome）は、完了・スキップ・失敗・一部だけ（`OutcomePartial`）・移動元を残した（`OutcomeCopiedSourceKept`）のいずれかで示す。
- 衝突の決定によるスキップ（Err が nil のもの）は「選択によりスキップ」と表示し、エラーとは区別する。
- `Details`（フォルダの中で完了以外になったエントリ）は、Space で展開する。
- `e` で英語の詳細（`OpError.Error()`）を出す。不具合の報告用。
- 全体の状態は、完了・一部にエラーがあります・中止しました、のいずれかで示す。

ごみ箱に入らなかった項目:

- ごみ箱に入らなかった項目（`KindTrashUnavailable`）があれば、「D 完全削除の確認へ」と案内し、§8.6 に進めるようにする。
- ごみ箱に入らないことが分かる時点は環境によって違う。Windows・Linux・cgo なしの macOS では計画の時点で、cgo ありの macOS では実行の後に分かる（fsops の doc.go）。どちらの場合も、この結果画面から同じ流れで扱う。

### 8.6 完全削除

```text
+- 完全削除の確認 -------------------------------------------+
|                                                            |
|  次の 2 項目はごみ箱に入れられません。                     |
|  完全に削除しますか？ 元に戻せません。                     |
|                                                            |
|    Z:\share\old.zip       2.1 GB                           |
|    Z:\share\tmp\          フォルダ                         |
|                                                            |
|  合計 313 ファイル、6.1 GB                                 |
|                                                            |
|  y 完全に削除する   n・Esc・Enter やめる                   |
+------------------------------------------------------------+
```

- `D` キーで直接行う場合と、§8.5 でごみ箱に入らなかった項目から進む場合の両方で、この画面を使う。
  - `D` キーのとき、1 行目の文は「次の n 項目を完全に削除します。」とする。
  - §8.5 から進んだとき、1 行目の文は「次の n 項目はごみ箱に入れられません。」とする。
- 画面を出す前に、対象の項目で `OpDelete` の計画を作り、合計のファイル数とバイト数を示す。
- fsops の `Plan` には項目ごとの合計がないため、項目ごとには、ファイルかフォルダかと、ファイルのサイズだけを出す（§11 の F5）。
- 確定は `y` だけで行う。Enter・Esc・`n` はやめる。うっかり Enter を押して消さないため（U2）。
- 項目が多いときは、先頭の数件と「ほか n 項目」を出す。

### 8.7 名前の変更と新しいフォルダ

```text
+- 名前の変更 ---------------------------------------------+
|                                                          |
|  報告書.docx                                             |
|  [報告書_最終|.docx                                  ]   |
|                                                          |
|  ! 同じ名前のものがあります                              |
|                                                          |
|  Enter 変更   Esc やめる                                 |
+----------------------------------------------------------+
```

名前の変更:

- カーソル行の項目だけを対象にする。複数の項目の一括変更は §14 に挙げる。
- 入力欄の初期値は今の名前で、カーソルは拡張子の前に置く。
- 名前を変更せずに Enter を押したら、何もしない。
  入力欄に出す文字列は表示用に加工したもの（§9.3）なので、変更したかどうかは入力があったかどうかで判断する。文字列の比較で判断してはいけない（U4）。
- `fsops.Rename` のエラーは入力欄の下に出し、入力欄は閉じない。`KindExist` なら「同じ名前のものがあります」、`KindInvalidName` なら「この名前は使えません」と出す。
- 大文字小文字だけ、または正規化だけが違う名前への変更もできる（fsops §11.3）。

新しいフォルダ:

- 名前の変更と同じ形の画面を使う。作ったら、カーソルを新しいフォルダに置く。
- fsops にはフォルダを作る関数がないため、追加する（§11 の F2）。

日本語の入力（IME）の動作は VU4 で確かめる。

## 9. 表示の規則

### 9.1 文字の幅

- 表示幅は次のように数える。
  - East Asian Width が W・F の文字: 2 桁
  - 結合文字: 0 桁
  - それ以外: 1 桁
- 幅が曖昧な文字（East Asian Width が A のもの。罫線、`…`、`○` など）が 1 桁か 2 桁かは、端末とフォントで変わる（VU2）。
  結果が分かるまでは、UI が自分で出す文字には幅が曖昧な文字を使わない。本書のモックが ASCII の枠と `~` を使っているのはこのため。
- 幅の計算は `textfmt` にまとめる。TUI フレームワークが内部で使う計算と一致することを確かめる（VU1）。

### 9.2 切り詰め

- 名前は、拡張子を残して途中を切り、`~` を入れる（例: `見積書_2026~.xlsx`）。
- パスは先頭側を切る（例: `C:\~\projects\tana`）。
- 切り詰めるのは表示だけ。切り詰めた文字列からパスを作ってはいけない（U4）。

### 9.3 制御文字と正規化

- 一覧では、次の文字を `?` に置き換えて、色を変えて出す。状態行では `\x1b` のような形で示す。
  - 制御文字（U+0000〜U+001F、U+007F〜U+009F）
  - 双方向の制御文字（U+202A〜U+202E、U+2066〜U+2069）。拡張子を偽装した名前（`.exe` を `.txt` のように見せるなど）に使われるため。
- macOS の NFD の名前（濁点が結合文字になっているもの）をそのまま出すか、表示用に NFC に変えるかは、VU3 の結果で決める。変える場合も、変えるのは表示だけ（U4）。

### 9.4 サイズと日時

- サイズは §15 の案で書く（1024 で割って `K`・`M`・`G`・`T` を付け、5 桁に収める）。状態行では、バイト数を 3 桁ごとに区切って出す。
- 更新日時は、今年のものは `MM-DD HH:MM`、それ以外は `YYYY-MM-DD` で書く。状態行では `YYYY-MM-DD HH:MM:SS` で書く。

### 9.5 色

- 種類ごと（フォルダ、リンク、ジャンクション、特殊なファイル、隠しファイル）と、マーク、カーソル行に色を付ける。
- 色だけで区別しない。種類はサイズの欄で、マークは `*` でも分かるようにする。
- 環境変数 `NO_COLOR` が設定されていれば、色を使わない。

## 10. 内部の構成

状態と goroutine:

- 画面の状態を変更するのは、イベントループの goroutine だけとする。
- 列挙・`NewPlan`・`Execute` は作業用の goroutine で行い、結果をメッセージとしてイベントループに送る。
- 進捗は、最新の値を 1 つだけ置ける場所に、fsops の `Progress` の呼び出しの中で書き込み、すぐに戻る。イベントループはその値を読んで描く。こうすれば、イベントループが遅れても fsops を待たせない。
- 1 つの `Plan` は 1 回だけ実行する（fsops §7.1）。やめた計画は捨てる。

端末とログ:

- 端末の状態（raw モード、代替画面）は、panic やシグナルで終わる場合も元に戻す。
- 環境変数 `TANA_LOG` にファイルのパスが指定されていれば、`OpError.Error()` などの英語の詳細をそのファイルに書く。
  fsops はログを出さない（CLAUDE.md の fsops の実装ルール）ため、記録は UI の側で行う。

テスト:

- `textfmt`: 幅・切り詰め・置き換えを、入力と期待値の表で確かめる。
- `listing`: `t.TempDir()` の中で、種類・隠し属性・並べ替えを確かめる。
  fsops の `testfs` は `internal/fsops` の外から import できないため、使えるようにするかは F1 と一緒に決める。
- `app`: キー入力を表すメッセージの列を与えて、状態の変化を確かめる。fsops は本物を使う（`t.TempDir()` の中だけ。CLAUDE.md のテストのルールと同じ）。
- `tui`: 80×24 と 120×40 で描いた画面の文字列を、`testdata` のゴールデンファイルと比べる。本書のモックをゴールデンファイルの出発点にする。
- 端末での実際の見え方・キー・IME は CI では確かめられないので、§12 の手動の確認で行う。

## 11. fsops への追加・変更の候補

どれも fsops の仕様の変更になる。PROMPTS.md の「仕様を変えたい」の手順で SPEC-fsops の変更案を作り、承認してから行う。

- **F1 一覧のための種類の判定・列挙**（v0.1 に必要）
  listing には次のものが必要になる。今は `lstatEntry`・`readDir`・`sysPath` がいずれも非公開である。
  - fsops と同じ種類の判定（fsops §14.1）
  - `\\?\` 形式への変換（fsops §8.2）
  - リンクを辿らない列挙

  方法の案は 2 つある。
  - 案 a: fsops に `Lstat`・`ReadDir` を公開する。
  - 案 b: これらを `internal/fsops` の下の別のパッケージ（例: `internal/fsops/fsinfo`）に切り出し、fsops と listing の両方から使う。

  fsops §1 で一覧は fsops の範囲外としているので、案 b をすすめる。一覧には、隠し属性・読み取り専用・リンク先も必要になる。

- **F2 フォルダの作成**（v0.1 に必要）
  `Mkdir(parent, name string) error` を加える。
  - 上書きしない（既存なら `KindExist`）。
  - 名前の検査は `Rename` と同じ（fsops §11.3）。
  - `\\?\` 形式への変換を通す。

- **F3 計画の進捗**（大きなフォルダで必要）
  `NewPlan` は走査中に何も返さないため、数十万件のフォルダでは計画の作成中に何も表示できない。走査した件数を知らせる方法を加える。

- **F4 ごみ箱に入らない理由**（あると親切）
  理由には、ネットワーク上、リムーバブル、ごみ箱の最大サイズを超える、ごみ箱が無効な設定、cgo なしのビルド、などがある。
  区別できれば、「大きすぎるためごみ箱に入りません」のように示せる。
  `OpError.Err` に理由ごとのエラーを入れ、UI が `errors.Is` で調べる形が考えられる。

- **F5 項目ごとの合計**（あると親切）
  `Plan` の合計は全体のものしかないため、§8.6 で項目ごとのファイル数・バイト数を出せない。

## 12. 要検証事項

fsops §20 と同じく、推測で決めずに試し、結果をこの節に追記する。

CI では端末の見え方や入力を確かめられない。そこで、TUI フレームワークの候補ごとに小さな確認用のプログラム（`cmd/tuiprobe`）を作る。このプログラムは、幅の確認用の文字列の表示、キー入力の記録、入力欄を持つ。
これを手元の Mac と、仮想マシンの Windows（PROMPTS.md の §4）で動かし、手で確かめる。

- **VU1** TUI フレームワークの選定。候補（Bubble Tea、tcell と tview など）を、次の観点で比べる。
  - Windows Terminal・conhost・Terminal.app・iTerm2 でのキー入力（Shift＋英字、Ctrl＋英字、Backspace、Esc の遅延、F キー）
  - 端末の大きさを変えたときの動作
  - 全角文字の幅の計算
  - 10 万行の一覧の描画速度
  - 描画のテストのしやすさ
  - 終了時と panic 時の端末の復元
- **VU2** 幅が曖昧な文字（罫線、`…`、`○` など）が、各端末・日本語のフォントで何桁になるか。罫線を使うかどうかを、この結果で決める。
- **VU3** macOS の NFD の名前（濁点・半濁点が結合文字のもの）が、各端末で正しく表示されるか。幅の計算が合うか。
- **VU4** 名前の入力欄での日本語の IME（Windows Terminal・conhost・Terminal.app）。
  - 変換中の文字がどこに表示されるか
  - 確定できるか
  - Backspace がどう動くか
- **VU5** Windows のごみ箱の確認ダイアログ（fsops §12.2 の `FOF_WANTNUKEWARNING`）がコンソールのプロセスから出たとき、前面に出るか、端末の後ろに隠れるか。
- **VU6** Windows の不正な UTF-16（対になっていないサロゲート）を含む名前が、Go の列挙でどういう文字列になるか。その名前を fsops に渡して、同じエントリを指せるか。
  指せない場合は fsops にも関わる（fsops I6）ので、fsops の要検証事項としても記録する。
- **VU7** 応答しないネットワークドライブや、スリープ中の外付けディスクを列挙したとき、どれくらい待たされるか。UI が固まらず、中止できるか（U5）。
- **VU8** 10 万件のフォルダの列挙・並べ替え・描画にかかる時間とメモリ。
- **VU9** conhost で、最低限の表示と操作ができるか（§15 の判断材料）。
