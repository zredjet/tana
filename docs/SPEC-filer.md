# tana 仕様書（ファイラー本体）

たたき台（2026-09-24。2026-09-26 改訂。同日、フェーズ12の実測を §9・§12・§15 に反映）。§15 の未決事項を決めてから確定する。

ファイル操作の仕様は `docs/SPEC-fsops.md` に書く。本書ではその節を「fsops §n」と書く。
TUI の土台（端末の入出力、文字の幅、キーの解釈、描画、入力欄）の仕様は `docs/SPEC-tui.md` に書く。本書ではその節を「tui §n」と書く。
fsops の不変条件（fsops §2）は、本書のどの部分よりも優先する。

## 1. 目的と範囲

tana は Windows と macOS で動くターミナルのファイラーである。キーボードだけで、フォルダの内容を見て、ファイルを操作する。

ファイル操作の安全性は fsops が保証する（I1〜I7）。UI の役割は次の 3 つである。

- fsops の計画と結果を正確に見せる。
- 利用者の決定をそのまま fsops に渡す。
- 利用者を迷わせない。

最初の版（v0.1）は、fsops を実際の画面から使えることを確かめるための最小限の版とする。v0.1 で扱うのは次のとおり。

- フォルダの閲覧（移動、マーク、隠しファイルの表示切り替え、再読み込み、パスを入力して移動）。画面の構成は §15 で決める（案は 2 つのペイン）
- ファイルを関連付けで開く
- コピー・移動・ごみ箱・完全削除・名前の変更・新しいフォルダ
- 確認、衝突の決定、進捗とキャンセル、結果の表示

それ以外は §14 に挙げる。

TUI のライブラリは使わず、端末の入出力から自作する（§4、tui §1）。

## 2. UI の原則

fsops の不変条件を UI の側で崩さないための約束。どの画面でも守る。

- **U1 上書き・マージを利用者に代わって決めない**
  衝突の決定の既定は「未選択」とする（fsops の `DecisionUnset`。スキップとして扱われる）。
  上書き・マージを設定するのは、利用者がその衝突で選んだ場合と、「すべてに適用」を選んだ場合だけ。
  例外として、自分自身への衝突（`Conflict.Self`。同じフォルダへのコピー）では、最初から自動リネームを選んでおく。既存のものを置き換えないため。

- **U2 完全削除は専用の確認を経た場合だけ**
  `OpDelete` は、§8.6 の確認画面で `y` を押した場合だけ実行する。
  ごみ箱に入らない項目を、UI が自動で完全削除に切り替えることはしない（fsops I5 の UI 側）。
  確認画面（§8.2・§8.3・§8.6）は、その画面を出す前に届いたキーで確定しない。計画を作っている間に打たれたキー（先行入力）は捨てる。
  貼り付けられた文字列は、入力欄に入れるだけで、コマンドとして解釈しない（tui §5）。

- **U3 結果を隠さない**
  エラーのある項目と、完了・スキップ以外の項目があれば、必ず結果画面を出す（§8.5）。警告だけの場合も、メッセージ行で知らせて、あとから見られるようにする。
  「移動元を残した」（`OutcomeCopiedSourceKept`）では、データが無事であることと、残したパスを示す。
  「ごみ箱に入ったか確かめられない」（`OutcomeTrashUnconfirmed`）では、完全に削除された可能性があることを示す。

- **U4 パスは列挙で得た名前から作る**
  fsops に渡すパスは、フォルダの列挙で得た名前（バイト列）をそのまま使って作る。
  表示用に加工した文字列（制御文字の置き換え、切り詰め、正規化をしたもの）からパスを作ってはいけない。

- **U5 UI を止めない**
  フォルダの列挙・計画・実行は、UI のイベントループとは別の goroutine で行う。時間がかかる処理は途中で中止できるようにする。
  列挙と計画の「中止」は、待つのをやめて結果を捨てることを指す。応答しないネットワークドライブでは OS の呼び出しそのものは止められず、作業用の goroutine は戻るまで残る。
  実行の中止は ctx で行い、`Execute` が戻るまで待つ（§8.4）。
  例外は、Windows でごみ箱の確認ダイアログが出た場合（fsops §12.2）。扱いは §8.4 に書く。

- **U6 ファイル名に端末を操作させない**
  制御文字（ESC など）や双方向の制御文字を含む名前を、そのまま端末に出力しない（§9.3）。描画の段階でも同じ置き換えを行う（tui T2）。

## 3. 対象環境

- Windows 10 / 11 では、Windows Terminal を主な対象とする。従来のコンソール（conhost）を対象にするかは §15 で決める。
- macOS では、Terminal.app を主な対象とし、iTerm2 でも確認する。
- 端末の大きさは 80 桁 × 24 行以上。これより小さいときは「端末が小さすぎます」とだけ表示する。
- 表示は日本語だけとする（fsopsctl と同じ）。
- Linux については、コンパイルが通ることだけを保証する（fsops §3 と同じ）。

## 4. 構成と依存

```
cmd/tana/            起動、引数
cmd/tuiprobe/        端末の実測と確認用のプログラム（§12）
internal/fsops/      ファイル操作（既存）
internal/term/       端末の入出力。OS ごとのコードはここに閉じる（tui §8）
internal/textwidth/  書記素クラスタと表示幅（tui §4）
internal/keys/       入力をキー・文字・貼り付けのイベントに変える（tui §5）
internal/screen/     セルの格子、領域、差分の出力（tui §6）
internal/lineedit/   1 行の入力欄の編集（tui §7）
internal/listing/    フォルダの列挙、種類・属性の判定、並べ替え（§6）
internal/textfmt/    切り詰め、制御文字の置き換え、サイズ・日時の書式（§9）
internal/msg/        Kind・Outcome・段階などの文言（§8.8）。fsopsctl からも使う
internal/app/        画面の状態と操作の流れ。端末の入出力に依存しない（§10）
internal/tui/        描画とキー入力。term・keys・screen を組み合わせたイベントループ
internal/platform/   OS ごとに違う処理（関連付けで開く、実行ファイルの判定、名前が . で始まるものを隠すか）。OS ごとのコードはここと term に閉じる
```

- `term`・`textwidth`・`keys`・`screen`・`lineedit` は TUI の土台で、仕様は SPEC-tui に書く。filer 固有の概念（ペイン、ファイル）を入れない。
- `listing`・`textfmt`・`msg`・`app` は、`term`・`keys`・`screen`・`tui` を import しない。
- `platform` は、標準ライブラリと `golang.org/x/sys` だけを使い、ほかの tana のパッケージを import しない（フェーズ18で加えた）。
- 画面の状態はすべて `app` が持つ。`tui` が行うのは、その状態を描くことと、キー入力を `app` へのメッセージに変えることだけ。
  例外として、表示形式（2 ペインと Yazi 風。§5.3）の選択は `tui` が持つ。`app` は表示形式を知らず、`tui` が求めたときだけ、
  操作中のペインの親フォルダの一覧とプレビュー（§6）を読む（フェーズ18で加えた）。
- この境界は `deps_test.go`（fsops と同じ方式）で確かめる。
- 依存:
  - リポジトリのすべてのパッケージで、import してよいのは標準ライブラリ、`golang.org/x/sys`、`golang.org/x/text` だけとする（fsops §4 と同じ）。
  - ほかのものが必要になったら、理由を添えて確認する。
  - これを、fsops の `deps_test.go` と同じ方式のテストで、リポジトリ全体について確かめる。
- `listing` が fsops の種類の判定と `\\?\` 形式の変換を使えるようにする方法は、§11 の F1 で決める。

画面の構成を後から変えられるようにする:

- 画面の構成（2 つのペイン、ミラーカラム、1 つのペイン）は、触ってから決める（§15）。決めた後も変わりうるので、`app` を特定の構成に依存させない。
- `app` は、ペインを「フォルダの表示（フォルダ、項目、カーソル、マーク）」の並びとして持つ。
- コピー・移動の行き先の決め方（反対側のペイン、yank と paste、パスの入力）は、ほかの処理から切り離す。
  fsops の `Request`（`Sources` と `DestDir`）はどの決め方にも対応する。yank と paste なら、yank の時点の項目が `Sources`、paste の時点のフォルダが `DestDir` になる。
- 計画 → 確認 → 衝突の決定 → 実行 → 結果の流れは、画面の構成に依存させない。
- こうして、構成の変更を `app` の一部と `tui` の描画の中に閉じる。

## 5. 画面の構成

表示形式は 2 ペイン（§5.1）と Yazi 風（§5.3）の 2 つで、`v` で切り替える。起動時は 2 ペイン（フェーズ18で決めた）。
どちらを残すか・既定にするかは、触ってから決める（§15）。

### 5.1 メイン画面

左右 2 つのペインと、その下の 3 行（状態行・メッセージ行・キーの案内）からなる。

```text
+= C:\Users\hiro\Documents ============++- D:\backup --------------------------+
|  ..                 <DIR>            ||  ..                 <DIR>            |
|  old-docs           <JCT> 2025-03-01 ||  2025               <DIR> 2025-12-28 |
|  projects           <DIR> 09-24 10:40||  写真               <DIR> 08-02 12:00|
| *写真               <DIR> 09-12 09:15||  議事録             <DIR> 09-01 10:00|
| *議事録             <DIR> 09-20 18:02||  archive.zip         2.3G 08-30 19:45|
|  latest             <LNK> 09-22 08:00||  報告書.docx         1.1M 09-20 09:00|
|  data.csv            128M 09-18 14:30||                                      |
|  README.md           3.1K 09-23 22:10||                                      |
|>*報告書.docx         1.2M 09-24 11:19||                                      |
|  見積書_2026~.xlsx    48K 09-10 16:05||                                      |
|                                      ||                                      |
+= 9 項目  マーク 3 ===================++- 5 項目 -----------------------------+
 報告書.docx   1,234,567 バイト   2026-09-24 11:19:05

 c コピー  m 移動  d ごみ箱  D 完全削除  r 名前  n 新しいフォルダ  ? ヘルプ
```

モックの読み方:

- 80 桁の例。行数は端末の高さに合わせる。
- `>` はカーソル行（実際の画面では反転表示）、`*` はマーク、`=` の枠は操作中のペインを表す。
- 枠は ASCII で書いている。罫線文字を使うかは VU2 の結果で決める。

各部分の内容:

- ペインの枠の上にはフォルダのパス、下には項目数とマークの数を出す。パスが長いときは先頭側を切り詰める（§9.2）。
- 各行には、マーク・名前・サイズ・更新日時を出す。名前以外の欄は幅を固定し、残りの幅を名前に使う。
- 80 桁では名前の欄が全角 8 文字程度しかない。ペインの内側の幅が狭いときは、更新日時の欄を隠して名前に回す（状態行には出る）。どの幅で隠すかは、ゴールデンファイルを作るときに決める。
- サイズの欄には、ファイルならサイズ（§9.4）を出す。ファイル以外は種類を示す。
  `<DIR>` はフォルダ、`<JCT>` はジャンクション、`<LNK>` はシンボリックリンク、`<SPC>` は特殊なファイル（fsops §14 の `TypeSpecial`）。
- 状態行には、カーソル行の項目について、名前（入りきらないときは §9.2 で切り詰める）、バイト数、秒までの更新日時を出す。リンクとジャンクションでは、リンク先も出す。
- メッセージ行には、直前の操作の結果の要約やエラー（「このフォルダを開けません: アクセス権がありません」など）を出す。次のキー入力で消す。

### 5.2 ダイアログ

- 確認・進捗・名前の入力などは、メイン画面の中央に重ねて出す。
- 衝突の決定と結果は一覧が長くなるので、画面全体を使う。

### 5.3 Yazi 風の表示（ミラーカラム）

左に親フォルダ、中央に操作中のペインのフォルダ、右にカーソル行の項目のプレビュー（§6）を並べる。フェーズ18で加えた。

```text
┌─ C:\Users\hiro\Documents ────────────────────────────────────────────── [1/2] ─┐
│ AppData │ ..                  <DIR>             │ 2025年度                     │
│ Desktop │ old-docs            <JCT> 2025-03-01  │ 2026年度                     │
│ Document│ projects            <DIR> 09-24 10:40 │ 議事録.docx                  │
│ Download│>写真                <DIR> 09-12 09:15 │ 予算.xlsx                    │
│ Music   │ 報告書.docx          1.2M 09-24 11:19 │                              │
└─ 15 項目  マーク 3 ───────────────────────────────────────────────────────────┘
 写真   フォルダ   2026-09-12 09:15:00

 v 表示  h 親へ  l 入る  Tab もう一方  Space マーク  g パス  ? ヘルプ  q 終了
```

- 列の幅の比は 1:4:3（Yazi の既定と同じ）。中央の列の各行は、2 ペインの 1 つのペインと同じ。
- 左の列は親フォルダの一覧で、今のフォルダの行に印を付ける。ボリュームのルートでは空。隠しファイルの規則は §6 と同じ。
- 枠の上には操作中のペインのパスと、どちらのペインを表示しているか（`[1/2]`）を出す。Tab で、もう一方のペインの表示に切り替える（タブのような扱い）。
- 2 つのペインの状態（フォルダ・カーソル・マーク）は、表示形式を切り替えても保つ。
- 状態行・メッセージ行・キーの案内は 2 ペインと同じ。
- コピー・移動の行き先の決め方（2 ペインでは反対側のペイン）は、フェーズ19で決める（yank と paste を想定する。§4）。

## 6. フォルダの一覧（listing）

起動時のフォルダ:

- `tana [フォルダ...]` で、表示するフォルダを指定する。2 ペインなら `tana [左 [右]]`。
- 省略したときは、すべてのペインで起動したフォルダを表示する。
- 前回の場所を覚えるのは後の版で行う。

列挙と種類の判定:

- 列挙と種類の判定は、fsops の `ReadDir`・`Lstat`（fsops §14.3）で行う。列挙ではリンクを辿らない。
  種類の判定は操作と同じ（fsops §14.1）。Windows ではジャンクションが `os.Lstat` で `ModeIrregular` に見えるため、Go のモードビットだけに頼らない。
- リンク・ジャンクションのフォルダには、Enter で入れる（Finder・エクスプローラーと同じ）。表示するパスはリンクのパスのままにする。
- 隠しファイルとして扱うのは次のもの。表示するかどうかは `.` キーで切り替える。既定は隠す。
  - Windows: `FILE_ATTRIBUTE_HIDDEN` が付いたもの（`FILE_ATTRIBUTE_SYSTEM` も付いたものを含む）。`FILE_ATTRIBUTE_SYSTEM` だけが付いたものは隠さない（エクスプローラーと同じ）。
    名前が `.` で始まるものは、隠しファイルとして扱わない（エクスプローラーと同じ）。
  - macOS: 名前が `.` で始まるものと、`UF_HIDDEN` が付いたもの
- 隠しファイルを隠すときは、隠れた項目のマークを外す。見えない項目を操作の対象にしないため。
- ボリュームのルート以外では、先頭に `..` を出す。

並べ替え:

- 並び順は、フォルダ・ジャンクション → リンク → その他とし、それぞれの中は名前順とする。
- リンクは、リンク先を調べずに並べる。リンク先の確認で待たされないようにするため。
- 名前の比較には、並べ替え用に作ったキーを使う。キーは、大文字小文字をそろえ、Unicode を正規化し、数字の並びを数値として比べられるようにしたもの。
- キーは比較にだけ使い、名前そのものは変えない（U4）。

読み込みの失敗と待ち時間:

- 列挙は別の goroutine で行う。
- 0.2 秒を超えたら「読み込み中…（Esc で中止）」を出す。Esc で中止し、元のフォルダに戻る（U5。中止は待つのをやめて結果を捨てること）。
  件数は出さない。fsops の `ReadDir` は一度に全部を返し、途中の件数が分からないため（フェーズ18で決めた）。
- フォルダに入れなかったとき（権限がない、消えているなど）は、元のフォルダに留まり、メッセージ行に理由を出す。
- 表示中のフォルダが消えていたときは、存在する祖先のうち最も近いフォルダを表示する。

プレビュー（Yazi 風の表示の右の列。フェーズ18で加えた）:

- フォルダ（リンク・ジャンクションのフォルダを含む）: 中身の一覧。隠しファイルの規則は一覧と同じ。`..` では親フォルダの中身。
- ファイル: 先頭（64 KiB まで）を fsops の `ReadHead`（§11 の F6）で読み、テキストなら先頭の行を出す。
  - 文字コードは UTF-8（BOM の有無を問わない）、BOM 付きの UTF-16、Shift_JIS を判定する。どれでもなければ「表示できないファイル」とする。NUL を含むものはバイナリとする。
  - タブは 4 桁ごとの空白に広げる。制御文字などは一覧と同じく置き換えて出す（U6）。行は折り返さずに列の幅で切る。
- それ以外（バイナリ、特殊なファイル、読めないもの）: 種類・サイズ・更新日時と、理由を出す。
- 中身が手元にないファイル（クラウドのファイルのうち、読むと取得が始まるもの）は読まない。
- 読み込みは作業用の goroutine で行う（U5）。カーソルが 0.1 秒止まってから読み、読み終わる前にカーソルが動いたら結果を捨てる。
- 画像・アーカイブの中身・構文の色分けはしない（§14）。

再読み込み:

- v0.1 で再読み込みするのは、ファイル操作の後（影響するペインだけ）と、`Ctrl+R` を押したときだけ。フォルダの監視による自動の更新は §14 に挙げる。
- 再読み込みの後は、カーソルを同じ名前（バイト単位で一致）の項目に置く。なければ同じ行の位置に置く。
- マークは、再読み込みの後も名前で保つ。
- ファイル操作で完了（`OutcomeDone`）になった項目のマークは外し、それ以外の項目のマークは残す。やり直しやすくするため。

## 7. キー操作

キーの割り当てはすべて仮。系統（あふ・FD 系か vim 系か）は §15 で決める。

| キー | 操作 |
|---|---|
| ↑ ↓（`j` `k`） | カーソルの移動 |
| PgUp PgDn Home End | ページ単位の移動、先頭、末尾 |
| Enter | フォルダに入る。ファイルなら関連付けで開く（macOS は `open`、Windows は `ShellExecute`） |
| Backspace | 親のフォルダへ |
| Tab | 操作するペインの切り替え |
| Space | マークの切り替え（カーソルを 1 行下へ） |
| `a` | すべてマークする・すべて外す |
| `c` | コピー（反対側のペインのフォルダへ） |
| `m` | 移動（反対側のペインのフォルダへ） |
| `d` | ごみ箱へ |
| `D` | 完全削除 |
| `r` | 名前の変更 |
| `n` | 新しいフォルダ |
| `g` | パスを入力して移動（Windows のドライブの切り替えもこれで行う） |
| `=` | 反対側のペインを同じフォルダにする |
| `.` | 隠しファイルの表示の切り替え |
| `v` | 表示形式（2 ペインと Yazi 風。§5.3）の切り替え |
| `h`・`l` | 親のフォルダへ・フォルダに入る（ファイルでは何もしない）。どちらの表示形式でも同じ |
| `Ctrl+R` | 再読み込み |
| `L` | 直前の操作の結果をもう一度見る |
| `?` | ヘルプ |
| `q` | 終了 |

- 操作の対象は、操作中のペインでマークした項目。マークがなければ、カーソル行の項目を対象にする。`..` は対象にしない。
- 左右の矢印キー（仮。§15）: 2 ペインでは、そのペインへ移る（すでにその側なら親のフォルダへ）。Yazi 風では、← で親のフォルダへ、→ でフォルダに入る（`h`・`l` と同じ）。
- Tab: 2 ペインでは操作するペインの切り替え。Yazi 風では表示するペインの切り替え（§5.3）。
- v0.1 では、ファイル操作の実行中はほかの操作を受け付けない（§8.4）。
- raw モードでは Ctrl+C はシグナルではなくキーとして届く（tui §8）。ファイル操作の実行中の Ctrl+C は、Esc と同じく中止の確認を出す。それ以外では何もしない。
- 次のキーは割り当てに使わない（フェーズ12の実測。§12.5）。
  - F11: macOS（デスクトップの表示）と Windows Terminal（全画面の切り替え）が取り、どの端末でも届かなかった。
  - Alt: Mac の Option は、既定では Alt ではなく文字を送る（Option＋A で「å」）。
  - Ctrl＋I・Ctrl＋M・Ctrl＋[: Tab・Enter・Esc と同じバイトで届く。
- Ctrl＋H は Backspace と区別できる（`0x08` と `0x7F`）。F1〜F10・F12 は届く（Mac では fn と一緒に押す）。

関連付けで開く:

- 実行ファイルは、開く前に「実行しますか」と確認を出す。
  - Windows: `.exe`・`.com`・`.bat`・`.cmd`・`.ps1`・`.vbs`・`.js`・`.msi`・`.scr`・`.lnk` など
  - macOS: `.app`・`.command`・`.tool` と、実行属性の付いたファイル
- Windows では、次のパスは `ShellExecute` に渡さずに「この名前のファイルは開けません」と出す（VU10 の結果。§12.7）。
  - 末尾が `.` や空白の要素を含むもの。`foo.cmd.` を渡すと、`\\?\` を付けても、隣の別のファイル `foo.cmd` が開かれた（`SHFileOperation` の fsops V4 と同じ）。
  - 予約名（`CON`・`NUL.txt` など）を含むもの。Windows 11 では正しいファイルが開かれたが、Windows 10 では確かめていないので、開かない。
  - 260 文字（UTF-16）以上のもの。`ShellExecute` は失敗した（`\\?\` を付けても同じ）。
- `ShellExecute` は、OS のスレッドを固定し、`CoInitializeEx`（アパートメントスレッド）をしてから呼ぶ。VU10 では無くても開けたが、`ShellExecute` の文書が推奨するため。

## 8. ファイル操作の流れ

### 8.1 共通の流れ

```text
対象を決める -> 計画（NewPlan） -> 確認画面 -> 衝突の決定（衝突があるときだけ）
  -> 実行（Execute） -> 進捗 -> 結果 -> 再読み込み
```

計画:

- 計画は別の goroutine で作る。
- 0.2 秒を超えたら「計画を作成中…（Esc で中止）」を出す。fsops の `NewPlan` は進捗を返さないため、件数は出せない（§11 の F3）。
- `NewPlan` が error を返したとき（リクエスト全体の問題。fsops §6.1）は、メッセージ行に理由を出して終わる。
  例: 反対側のペインのフォルダが消えていたときは「コピー先のフォルダが見つかりません」と出す。
- 計画を作っている間に届いたキーは捨てる（U2）。

実行の設定:

- v0.1 では、`ExecOptions` のゼロ値（`LinkKeep`・`VerifySize`・`SyncMoveOnly`）で実行する。設定できるようにするのは、設定ファイルと一緒に後の版で行う。
- そのため `KindLinkSkipped`（`LinkSkip` のときだけ）は、v0.1 の結果には現れない。

実行前にやめる場合と、時間が空いた場合:

- 実行前（確認画面・衝突の画面）で Esc を押したら、計画を捨てて何もしない。`NewPlan` はファイルシステムを変更しないので、元に戻すものはない。
- 計画を作ってから実行するまでに時間が空いても、UI では何もしない。計画の後に起きた変化は fsops が安全に扱い、結果で報告する（fsops §7.3）。

両方のペインが同じフォルダの場合:

- コピーは、自分自身への衝突になる（自動リネームを選んだ状態で始まる。U1）。
- 移動は、項目ごとに `KindSameFile` になる。

### 8.2 確認画面

```text
+- コピー -------------------------------------------------+
|                                                          |
|  3 項目を D:\backup へコピーします                       |
|  合計 58 ファイル、1.3 GB                                |
|                                                          |
|  ! 衝突 125 件（トップレベル 3 件）                      |
|  ! 空き容量が足りない見込みです（空き 900 MB）           |
|                                                          |
|  Enter 衝突の確認へ   Esc やめる                         |
+----------------------------------------------------------+
```

確認画面に出すもの:

- 項目数、合計のファイル数とバイト数（`Plan.TotalFiles()`・`Plan.TotalBytes()`）、移動先。
  - 同一ボリュームの移動とごみ箱では `TotalBytes()` が 0 になる（fsops §6.3）。そのときはバイト数を出さない。
- 次のものがあれば、行の先頭に `!` を付けて示す。
  - 実行されない項目（`Item.Err` がある項目）と、項目ごとの理由（§8.8）。すべての項目が実行されないときは、実行できないので Esc で閉じるだけにする。
  - 衝突の件数。衝突があれば、Enter で衝突の画面へ進む。なければ、Enter で実行する。
  - 警告（`Plan.Warnings()`）。空き容量が足りない見込み、フォルダの中を読めなかった、など。警告があっても実行はできる（fsops §6.4）。

ごみ箱の場合:

- 「n 項目をごみ箱に入れます」と出す。
- ごみ箱では fsops が中身を数えない（fsops §6.3）ので、合計は出さない。
- ごみ箱に入らない項目（計画の時点で分かった `KindTrashUnavailable`）には「ごみ箱に入らないため実行しません」と示す。実行の後、§8.6 で完全削除するかを聞く。

その他:

- 完全削除では、この画面ではなく §8.6 の画面を使う。
- v0.1 では、衝突も警告もないときも、この画面を省かない。省く設定は、設定ファイルと一緒に後の版で加える。

### 8.3 衝突の決定

```text
 衝突の確認   コピー  C:\Users\hiro\Documents -> D:\backup
 衝突 125 件（トップレベル 3 件）  未選択 122 件（未選択はスキップします）
--------------------------------------------------------------------------------
  名前                 コピー元             コピー先             決定
  写真/                フォルダ             フォルダ             未選択
    （内側の衝突 120 件。マージを選ぶと表示します）
  議事録/              フォルダ             フォルダ             マージ
    2026-09-01.md       4.0K 09-01 10:00     4.0K 09-01 10:00    未選択
    2026-09-08.md       5.2K 09-08 10:00 新  4.1K 09-08 09:00    上書き
> 報告書.docx           1.2M 09-24 11:19 新  1.1M 09-20 09:00    上書き
--------------------------------------------------------------------------------
 この行: s スキップ  o 上書き  r 自動リネーム  m マージ
 すべて: S スキップ  O 上書き  N 新しいときだけ上書き  R 自動リネーム  M マージ
 Enter 実行  Esc やめる  Space 展開・折りたたみ  u 未選択だけ表示
```

`新` は更新日時が新しい方を示す（2 秒以内の差は同じとみなす。下の `N` を参照）。`未選択` は暗く表示する。

一覧の並べ方:

- トップレベルの衝突を計画の順に並べる。
- フォルダ同士の衝突の内側の衝突（`Conflict.Parent` が 0 でないもの）は、親の下に字下げして出す。
- 内側の衝突は、親がマージのときだけ意味を持つ（fsops §6.3）。親がマージでなければ、件数だけを 1 行で出して折りたたむ。
- Space で展開・折りたたみを切り替える。
- 衝突が数百件以上になる場合を想定し、一覧は画面に入る分だけを描く。
- `u` で、未選択の衝突だけを表示する。

1 行ずつの決定（小文字のキー）:

- 各行では、その行で使える決定だけを選べる（fsops §9.1）。
  - ファイル同士: スキップ・上書き・自動リネーム
  - フォルダ同士: スキップ・自動リネーム・マージ
  - 種類が違う場合と、自分自身への衝突: スキップ・自動リネーム
- 使えない決定のキーは暗く表示する。押しても何もせず、メッセージ行に理由を出す。

まとめての決定（大文字のキー）:

- 大文字のキーは、画面に出ているかどうかにかかわらず、その決定が使えるすべての衝突（内側の衝突を含む）に同じ決定を設定する。
- その決定が使えない衝突は変えずに、「n 件は種類が合わないため変更しませんでした」と出す。
- `N`（新しいときだけ上書き）は、ファイル同士の衝突のうち、コピー元の更新日時が新しいものを上書きに、それ以外をスキップにする。比べる更新日時は計画の時点のもの（`SrcInfo`・`DstInfo`）。
  - 2 秒以内の差は同じとみなし、スキップにする。FAT32 の更新日時は 2 秒単位なので、USB メモリへ一度コピーしたファイルが毎回「新しい」ことにならないようにするため。

警告:

- `Plan.Warnings()` の空き容量の警告は、その時点の決定で計算し直される（fsops §6.4）。決定を変えたら、ヘッダに最新の警告を出す。

実行:

- Enter で、その時点の決定で実行する。
- 未選択の衝突がスキップになることを、ヘッダに常に出しておく（U1）。

### 8.4 進捗とキャンセル

```text
+- コピー中 -----------------------------------------------+
|                                                          |
|  議事録\2026-09-08.md                                    |
|  [##################----------------------]  45%         |
|  ファイル 26 / 58      597 MB / 1.3 GB                   |
|  毎秒 85 MB   残り 約 9 秒   経過 7 秒                   |
|                                                          |
|  Esc 中止                                                |
+----------------------------------------------------------+
```

進捗画面に出すもの:

- 題名には段階（`Progress.Stage`）を出す。段階は、コピー中・移動中・検証中・移動元を削除中・ごみ箱へ移動中・削除中のいずれか。
- 処理中のパス、ファイル数、バイト数、進捗の棒を出す。
- 速度・残り時間・経過時間は UI が計算する。

進捗の受け取り方:

- fsops の `Progress` は `Execute` の goroutine から呼ばれ、すぐに戻る必要がある（fsops §16）。
- UI は最新の値だけを受け取り、描画は UI のイベントループで行う（§10）。

キャンセル:

- Esc（または Ctrl+C）を押すと、キャンセルの確認を出す。

```text
+- 中止の確認 -----------------------------------+
|                                                |
|  中止しますか？                                |
|  書きかけのファイルは残りません。              |
|  完了した項目はそのまま残ります。              |
|                                                |
|  y 中止する   n 続ける                         |
+------------------------------------------------+
```

- `y` を押したら ctx をキャンセルし、`Execute` が戻るまで「中止しています…」を出す。戻ったら結果画面を出す。

応答がなくなった場合:

- 応答しないネットワークドライブなどで、「中止しています…」のまま `Execute` が戻らないことがある（OS の呼び出しは ctx で止められない）。
- 一定の時間（案: 10 秒）戻らなければ、「応答がありません。終了できますが、次のものが残る場合があります」と出し、`Q` で終了できるようにする。
  残りうるものは fsops の doc.go の「保証すること」の一覧（一時ファイル、移動元と移動先の両方にあるもの、など）から示す。

Windows のごみ箱の確認ダイアログ:

- Windows のごみ箱では、Windows が完全削除の確認ダイアログを出すことがある。その間 `Execute` は止まっていて、ctx では中断できない（fsops §12.2）。
- ごみ箱へ移動中に 3 秒以上進捗が変わらなければ、「Windows の確認ダイアログが開いている可能性があります（ほかのウィンドウを確認してください）」と出す。
- ダイアログが前面に出るかどうかは VU5 で確かめる。

### 8.5 結果

```text
 移動の結果: 一部にエラーがあります   C:\Users\hiro\Documents -> D:\backup
 移動元を残した 1   失敗 1   スキップ 1   完了 1
--------------------------------------------------------------------------------
> 移動元を残した 写真/            移動先は完成。移動元の 2 件を残しました
                   IMG_0012.jpg   コピーの後に変更されたため残しました
                   IMG_0013.jpg   使用中のため残しました
  失敗           data.csv         ほかのアプリが使用中です
  スキップ       報告書.docx      選択によりスキップ
  完了           議事録/          （選択によるスキップ 1 件）
--------------------------------------------------------------------------------
 Space 詳細の展開・折りたたみ   e 英語の詳細（ログ用）   Enter 閉じる
```

結果画面を出す場合と出さない場合:

- 次のどれかに当たるときは、結果画面を出す。
  - `Status` が `StatusCanceled` のとき
  - `Err` のある項目があるとき（`Details` の中を含む）
  - Outcome が完了・スキップ以外（失敗・一部だけ・移動元を残した・ごみ箱に入ったか確かめられない）の項目があるとき
- それ以外は結果画面を出さず、メッセージ行に出す。
  - すべて完了で警告もないとき: 「3 項目をコピーしました」
  - 衝突の決定によるスキップ（`Err` が nil）があるとき: 「2 項目をコピーしました（選択によるスキップ 1 件）」。利用者が自分で選んだことなので、画面は出さない。
  - 警告（`ItemResult.Warnings`。メタデータを引き継げなかった、など）があるとき: 「3 項目をコピーしました。一部の属性を引き継げませんでした（L で詳細）」
    exFAT などへのコピーでは、多くのファイルで `KindMetadata` の警告が出うる（fsops の V6）。そのたびに画面を出すと煩わしいため。
- `L` キーで、直前の操作の結果画面をもう一度出せる。

一覧の並べ方と表示:

- 問題のあるもの（ごみ箱に入ったか確かめられない・移動元を残した・失敗・一部だけ）を先に並べ、次にスキップ、最後に完了を並べる。同じ区分の中は計画の順。
- 各項目の結果（Outcome）は、次のいずれかで示す。
  - 完了（`OutcomeDone`）
  - スキップ（`OutcomeSkipped`）
  - 失敗（`OutcomeFailed`）
  - 一部だけ（`OutcomePartial`）
  - 移動元を残した（`OutcomeCopiedSourceKept`）
  - ごみ箱に入ったか確かめられない（`OutcomeTrashUnconfirmed`）。「元の場所から消えましたが、ごみ箱に入ったことを確かめられません（完全に削除された可能性があります）」と出す。
- 「一部だけ」の意味は、実際に使った方式（`ItemResult.Method`）で変わる（fsops §7.4）。方式ごとに次のように説明する。
  - `MethodCopy`: コピー先に途中までの結果があります。コピー元は変わっていません
  - `MethodRename`: 一部は移動先へ移り、下の一覧のものは移動元に残っています
  - `MethodCopyThenRemove`: 移動元はすべて残っています。移動先に途中までコピーしたものがあります
  - `MethodRemove`: 一部は削除され、下の一覧のものは残っています
- 衝突の決定によるスキップ（Err が nil のもの）は「選択によりスキップ」と表示し、エラーとは区別する。
- `Details`（フォルダの中で完了以外になったエントリ）は、Space で展開する。
- `e` で英語の詳細（`OpError.Error()`）を出す。不具合の報告用。
- 全体の状態は、完了・一部にエラーがあります・中止しました、のいずれかで示す。

ごみ箱に入らなかった項目:

- ごみ箱に入らなかった項目があれば、「D 完全削除の確認へ」と案内し、§8.6 に進めるようにする。
- 対象にするのは、Outcome が `OutcomeFailed` で、Kind が `KindTrashUnavailable` の項目だけ。Kind だけで選んではいけない。
  `OutcomeTrashUnconfirmed` の項目も Kind が `KindTrashUnavailable` になりうる（fsops §7.4）が、元の場所から消えているので、完全削除を勧めない。
- ごみ箱に入らないことが分かる時点は環境によって違う。Windows・Linux・cgo なしの macOS では計画の時点で、cgo ありの macOS では実行の後に分かる（fsops の doc.go）。どちらの場合も、この結果画面から同じ流れで扱う。

### 8.6 完全削除

```text
+- 完全削除の確認 -------------------------------------------+
|                                                            |
|  次の 2 項目はごみ箱に入れられません。                     |
|  完全に削除しますか？ 元に戻せません。                     |
|                                                            |
|    Z:\share\old.zip       2.1 GB                           |
|    Z:\share\tmp\          フォルダ                         |
|                                                            |
|  合計 313 ファイル、6.1 GB                                 |
|                                                            |
|  y 完全に削除する   n・Esc・Enter やめる                   |
+------------------------------------------------------------+
```

- `D` キーで直接行う場合と、§8.5 でごみ箱に入らなかった項目から進む場合の両方で、この画面を使う。
  - `D` キーのとき、1 行目の文は「次の n 項目を完全に削除します。」とする。
  - §8.5 から進んだとき、1 行目の文は「次の n 項目はごみ箱に入れられません。」とする。
- 画面を出す前に、対象の項目で `OpDelete` の計画を作り、合計のファイル数とバイト数を示す。
- fsops の `Plan` には項目ごとの合計がないため、項目ごとには、ファイルかフォルダかと、ファイルのサイズだけを出す（§11 の F5）。
- 確定は `y` だけで行う。Enter・Esc・`n` はやめる。うっかり Enter を押して消さないため（U2）。
- 画面を出す前に届いたキーでは確定しない（U2）。
- 項目が多いときは、先頭の数件と「ほか n 項目」を出す。

### 8.7 名前の変更と新しいフォルダ

```text
+- 名前の変更 ---------------------------------------------+
|                                                          |
|  報告書.docx                                             |
|  [報告書_最終|.docx                                  ]   |
|                                                          |
|  ! 同じ名前のものがあります                              |
|                                                          |
|  Enter 変更   Esc やめる                                 |
+----------------------------------------------------------+
```

名前の変更:

- カーソル行の項目だけを対象にする。複数の項目の一括変更は §14 に挙げる。
- 入力欄の初期値は今の名前で、カーソルは拡張子の前に置く。
- 入力欄は `lineedit`（tui §7）を使う。
  - 入力欄が持つのは元の名前の文字列で、制御文字の置き換えなど（表示する形への置き換え。tui §4）は描画のときだけ行う。NFD の名前も NFC に変えない（§9.3）。
    こうしないと、表示のために `?` に置き換えた文字が、そのまま新しい名前に入ってしまう（U4）。
  - カーソルは書記素クラスタ（利用者から見た 1 文字）の単位で動かす。結合文字の途中に文字を入れない。
- 名前を変更せずに Enter を押したら、何もしない。
  変更したかどうかは入力があったかどうかで判断する。表示用の文字列との比較で判断してはいけない（U4）。
- 貼り付けられた文字列は、改行を除いて入力欄に入れる。
- `fsops.Rename` のエラーは入力欄の下に出し、入力欄は閉じない。`KindExist` なら「同じ名前のものがあります」、`KindInvalidName` なら「この名前は使えません」と出す。
- 大文字小文字だけ、または正規化だけが違う名前への変更もできる（fsops §11.3）。

新しいフォルダ:

- 名前の変更と同じ形の画面を使う。作ったら、カーソルを新しいフォルダに置く。
- fsops にはフォルダを作る関数がないため、追加する（§11 の F2）。

日本語の入力（IME）の動作は VU4 で確かめる。

### 8.8 Kind と表示する文言

fsops はメッセージを作らない（fsops §17）。UI が `Kind` から次の文言を作る。
文言は `internal/msg` にまとめ、fsopsctl もこれを使う（§4）。すべての Kind に文言があることをテストで確かめる。

| Kind | 文言 | 補足 |
|---|---|---|
| `KindNotFound` | 見つかりません | |
| `KindExist` | 同じ名前のものがあります | 実行の結果では「計画の後に同じ名前のものができたため、スキップしました」 |
| `KindPermission` | アクセス権がありません | |
| `KindLocked` | ほかのアプリが使用中です | |
| `KindReadOnly` | 読み取り専用です | |
| `KindNoSpace` | 空き容量が足りません | 着手前に打ち切られた項目では「空き容量が足りないため、実行しませんでした」 |
| `KindNotEmpty` | フォルダが空でないため削除できません | |
| `KindLinkUnsupported` | この場所にはリンクを作れません | ジャンクションのコピーでは「ジャンクションはコピーしません」（fsops §14.2） |
| `KindUnsupportedType` | この種類のファイルは扱えません | |
| `KindTrashUnavailable` | ごみ箱に入れられません | 理由を区別するかは §11 の F4 |
| `KindDestInsideSource` | コピー先がコピー元のフォルダの中にあります | |
| `KindSameFile` | 移動元と移動先が同じです | |
| `KindSourceChanged` | 処理中に変更されました | 移動元の削除では「コピーの後に変更されたため残しました」 |
| `KindDestChanged` | 処理中にコピー先・移動先のフォルダやファイルが変更されました | |
| `KindInvalidName` | この名前は使えません | |
| `KindNameForm` | 文字の表現（NFC・NFD）の違いで、このボリュームでは扱えない名前です | macOS の exFAT（fsops §8.5） |
| `KindInvalidRequest` | 指定が正しくありません | UI の不具合の可能性が高い。英語の詳細をログに残す |
| `KindCanceled` | 中止しました | |
| `KindMetadata` | 更新日時などを引き継げませんでした（データは無事です） | |
| `KindFileTooLarge` | コピー先のファイルシステムには大きすぎるファイルです | FAT32 は 4 GB 未満まで（fsops §10.6） |
| `KindMountPoint` | 別のボリュームがマウントされたフォルダです（中は削除しません） | fsops §13.1 |
| `KindVerifyFailed` | コピーした内容が元と一致しませんでした | fsops §10.4 |
| `KindSyncFailed` | ディスクへの書き込みを確定できませんでした | fsops §10.5 |
| `KindLinkSkipped` | リンクは設定によりコピーしませんでした | エラーではない（fsops §14.2）。v0.1 では現れない（§8.1） |
| `KindCrossDevice` | — | 結果には現れない（fsops §17）。現れたら `KindUnknown` と同じに扱う |
| `KindUnknown` | 予期しないエラーです | `e` で英語の詳細を見られることを案内する |

- `OpError.OnDest` が真のときは、文言の前に「コピー先・移動先で: 」を付ける（fsops §17）。利用者が、コピー元の問題と取り違えないようにするため。

## 9. 表示の規則

### 9.1 文字の幅

- 表示幅は、書記素クラスタ（利用者から見た 1 文字）ごとに `textwidth` で数える（tui §4）。`screen`・`lineedit`・`textfmt` はすべて `textwidth` を使う。
- 幅の規則は、各端末で実測した結果（VU2・VU3。§12.5）で決めた。規則は tui §4 に書き、実測の結果を `textwidth` のテストの期待値にする。
  - 日本語の文字（全角、半角カナ、NFD の濁点）の幅は、主な 3 端末（Terminal.app・iTerm2・Windows Terminal）で一致した。
  - 絵文字の並び（ZWJ でつないだもの、肌の色の修飾、VS16 付き、国旗、キーキャップ、タグ）の幅と描き方は、端末ごとに違った。
    これらは表示で簡略な形に置き換える（§9.3、tui §4）。
- 幅が曖昧な文字（East Asian Width が A のもの）は 1 桁として扱う。主な 3 端末の既定の設定で 1 桁だった。conhost（日本語の環境）は多くを 2 桁にする。
- UI が自分で出す文字:
  - 罫線（U+2500〜U+257F）は使ってよい。4 端末とも 1 桁だった（VU2）。本書のモックは ASCII の枠のままだが、枠は罫線に変えてよい。
  - ほかの幅が曖昧な文字（`…`・`○`・`※`・`→`・`×` など）は使わない。conhost で 2 桁になるため。切り詰めの印は `~` のままとする。
- 名前の幅の計算が端末とずれても、ずれがほかの欄やペインに広がらないように、欄ごとに位置を指定して描く（tui T5・T6）。
  ただし Terminal.app では、複数の符号位置からなる書記素クラスタがある行は、位置を指定してもずれる（tui T6）。そのため、そうしたクラスタは簡略な形にしてから描く。
- 欄と欄の間には、空白か区切り（罫線など）を置く。欄の端の書記素クラスタが、隣の欄の書記素クラスタと結合しないようにするため。
  Windows Terminal と iTerm2 は、位置を指定し直しても、左のセルと結合しうる書記素クラスタ（ハングルの字母、ZWJ の後の絵文字など）をまとめてしまう（tui §9 の VT7。フェーズ16で決めた）。

### 9.2 切り詰め

- 名前は、拡張子を残して途中を切り、`~` を入れる（例: `見積書_2026~.xlsx`）。
- パスは先頭側を切る（例: `C:\~\projects\tana`）。
- 切り詰めるのは表示だけ。切り詰めた文字列からパスを作ってはいけない（U4）。
- 書記素クラスタの途中では切らない。

### 9.3 制御文字と正規化

- 一覧では、次の文字を `?` に置き換えて、色を変えて出す。状態行では `\x1b` や `\u202e` のような形で示す。
  - 制御文字（U+0000〜U+001F、U+007F〜U+009F）
  - 双方向の制御文字（U+202A〜U+202E、U+2066〜U+2069）と、方向の印（U+200E LRM、U+200F RLM、U+061C ALM）。拡張子を偽装した名前（`.exe` を `.txt` のように見せるなど）に使われるため。
  - 行区切り・段落区切り（U+2028、U+2029）
  - 不正な UTF-8 のバイト。状態行では `\xNN` の形で示す。
    Windows の、対になっていないサロゲートを含む名前は、Go 1.21 以降では WTF-8（不正な UTF-8）の文字列として列挙され、そのまま OS に渡すと同じエントリを指す（VU6 で確かめた。§12.5）。表示では置き換え、パスには元のバイト列を使う（U4）。
  - 見えない書記素クラスタ（既定で無視される文字（ZWSP・ZWJ・WJ・BOM・SHY など）だけからなるもの、結合文字で始まるもの。tui §4）。
    端末によって幅が 0 桁か 1 桁かで割れ、名前の偽装にも使われるため。状態行では `\u200b` のような形で示す。
- 絵文字の並びのうち、端末によって幅と描き方が割れるもの（tui §4 の不安定な書記素クラスタ）は、一覧では簡略な形（👨‍👩‍👧 → 👨、❤️ → ❤、国旗 → `?` など）にして、色を変えて出す。
  状態行では、置き換えた部分を `\u{1f468}\u{200d}…` のような符号位置の形で示す。置き換えるのは表示だけ（U4）。
- macOS の NFD の名前（濁点が結合文字になっているもの）は、そのまま出す。表示用に NFC に変えない（VU3。§12.5）。
  - 主な 3 端末では、NFD の名前は NFC と同じに表示され、幅も同じだった。
  - NFC に変えると、NFC と NFD で名前だけが同じ 2 つのファイル（macOS 以外のボリュームでは並びうる）が、同じ名前に見えてしまう。
  - conhost では、濁点が別の 2 桁に出て崩れる（VU9 の材料）。

### 9.4 サイズと日時

- サイズは 1024 で割って `K`・`M`・`G`・`T` を付け、5 桁に収める（エクスプローラーと同じく 1024 で割る）。状態行では、バイト数を 3 桁ごとに区切って出す。
- 確認画面・進捗画面の `MB`・`GB` も 1024 で割った値とする。
- 更新日時は、今年のものは `MM-DD HH:MM`、それ以外は `YYYY-MM-DD` で書く。状態行では `YYYY-MM-DD HH:MM:SS` で書く。

### 9.5 色

- 種類ごと（フォルダ、リンク、ジャンクション、特殊なファイル、隠しファイル）と、マーク、カーソル行に色を付ける。
- 色だけで区別しない。種類はサイズの欄で、マークは `*` でも分かるようにする。
- 環境変数 `NO_COLOR` が設定されていれば、色を使わない。

## 10. 内部の構成

状態と goroutine:

- 画面の状態を変更するのは、イベントループの goroutine だけとする。
- 列挙・`NewPlan`・`Execute` は作業用の goroutine で行い、結果をメッセージとしてイベントループに送る。
- 進捗は、最新の値を 1 つだけ置ける場所に、fsops の `Progress` の呼び出しの中で書き込み、すぐに戻る。イベントループはその値を読んで描く。こうすれば、イベントループが遅れても fsops を待たせない。
- 1 つの `Plan` は 1 回だけ実行する（fsops §7.1）。やめた計画は捨てる。
- 作業用の goroutine は、panic を回収してイベントループに渡す。別の goroutine の panic は、端末を戻す処理を通らずにプロセスを終わらせるため（tui T1）。

端末とログ:

- 端末の状態（raw モード、代替画面、Windows のコンソールモード）は、panic やシグナルで終わる場合も元に戻す（tui T1）。
- シグナル（SIGINT・SIGTERM・SIGHUP）と、Windows のコンソールを閉じる通知（`CTRL_CLOSE_EVENT`。約 5 秒で強制終了される）を受けたとき:
  - ファイル操作の実行中なら、ctx をキャンセルし、短い時間だけ `Execute` が戻るのを待つ。
  - 端末を元に戻して終わる。
  - 強制終了されても、fsops の不変条件は保たれる（fsops の doc.go の「保証すること」）。
- 環境変数 `TANA_LOG` にファイルのパスが指定されていれば、`OpError.Error()` などの英語の詳細をそのファイルに書く。
  fsops はログを出さない（CLAUDE.md の fsops の実装ルール）ため、記録は UI の側で行う。

テスト:

- TUI の土台（`term`・`textwidth`・`keys`・`screen`・`lineedit`）のテストは、tui の各節に書く。
- `textfmt`: 切り詰め・置き換え・サイズ・日時の書式を、入力と期待値の表で確かめる。
- `listing`: 隠しファイルの判定・並べ替えを、fsops の `Entry` の値を与えて確かめる（純粋な関数にする）。
  実際の属性の読み取り（隠し属性・読み取り専用・種類）は fsops のテストが `testfs` で確かめる（F1 で決めた）。
- `app`: キー入力を表すメッセージの列を与えて、状態の変化を確かめる。fsops は本物を使う（`t.TempDir()` の中だけ。CLAUDE.md のテストのルールと同じ）。
  先行入力を捨てること（U2）と、隠しファイルを隠したときにマークを外すこと（§6）も確かめる。
- `tui`: 80×24 と 120×40 で描いた `screen` の格子を文字列にして、`testdata` のゴールデンファイルと比べる。本書のモックをゴールデンファイルの出発点にする。
  格子から端末への出力が正しいことは、`screen` のテストで確かめる（tui §6）。
- 端末での実際の見え方・キー・IME は CI では確かめられないので、§12 の手動の確認で行う。

## 11. fsops への追加・変更の候補

どれも fsops の仕様の変更になる。PROMPTS.md の「仕様を変えたい」の手順で SPEC-fsops の変更案を作り、承認してから行う。

- **F1 一覧のための種類の判定・列挙**（v0.1 に必要）→ フェーズ17で案 a に決め、fsops に `Lstat`・`ReadDir`・`Readlink` を加えた（fsops §14.3）。
  listing には次のものが必要になる。今は `lstatEntry`・`readDir`・`sysPath` がいずれも非公開である。
  - fsops と同じ種類の判定（fsops §14.1）
  - `\\?\` 形式への変換（fsops §8.2）
  - リンクを辿らない列挙

  方法の案は 2 つある。
  - 案 a: fsops に `Lstat`・`ReadDir` を公開する。
  - 案 b: これらを `internal/fsops` の下の別のパッケージ（例: `internal/fsops/fsinfo`）に切り出し、fsops と listing の両方から使う。

  fsops §1 で一覧は fsops の範囲外としているので、たたき台では案 b をすすめていた。一覧には、隠し属性・読み取り専用・リンク先も必要になる。
  ただし、次の懸念がある。フェーズ17で比べ直し、案 a に決めた（分類をそのまま使え、fsops の既存の経路を変えずに済むため）。
  - 一覧でも、エラーを Kind で分類して文言を出したい（「このフォルダを開けません: アクセス権がありません」）。
  - エラーの分類（`errors_*.go`）は fsops の `OpError`・`Kind` に結びついているので、案 b では分類も切り出す必要があり、fsops の変更が大きくなる。
  - 案 a なら、fsops の中で分類した `*OpError` をそのまま返せる。

- **F2 フォルダの作成**（v0.1 に必要）→ フェーズ17で加えた（fsops §11.4）。
  `Mkdir(parent, name string) error` を加える。
  - 上書きしない（既存なら `KindExist`）。
  - 名前の検査は `Rename` と同じ（fsops §11.3）。
  - `\\?\` 形式への変換を通す。

- **F3 計画の進捗**（大きなフォルダで必要）
  `NewPlan` は走査中に何も返さないため、数十万件のフォルダでは計画の作成中に何も表示できない。走査した件数を知らせる方法を加える。

- **F4 ごみ箱に入らない理由**（あると親切）
  理由には、ネットワーク上、リムーバブル、ごみ箱の最大サイズを超える、ごみ箱が無効な設定、cgo なしのビルド、などがある。
  区別できれば、「大きすぎるためごみ箱に入りません」のように示せる。
  `OpError.Err` に理由ごとのエラーを入れ、UI が `errors.Is` で調べる形が考えられる。

- **F5 項目ごとの合計**（あると親切）
  `Plan` の合計は全体のものしかないため、§8.6 で項目ごとのファイル数・バイト数を出せない。

- **F6 ファイルの先頭の読み取り**（プレビューに必要）→ フェーズ18で加えた（fsops §14.4）。
  `ReadHead(path string, max int) (Head, error)` を加える。fsops に置く理由は次の 2 つ。
  - Windows で `\\?\` 形式に変換しないと、`foo.` を読むつもりで隣の `foo` を読む（VU10 と同じ問題。U4）。
  - FIFO やデバイスを開いて止まらないように、通常のファイルだけを読むことを保証する。

## 12. 要検証事項

fsops §20 と同じく、推測で決めずに試し、結果をこの節に追記する。TUI の土台の実装に関わる要検証事項は tui §9 に書く。

### 12.1 確かめ方

CI では端末の見え方や入力を確かめられない。そこで、確認用のプログラム `cmd/tuiprobe` を作り、各端末で動かす。

- `tuiprobe width`: 文字幅の実測（VU2・VU3）。
  - raw モードで、各文字列を 1 桁目から出し、カーソル位置の問い合わせ（`ESC[6n`）で、端末が実際に進めた桁数を得る。目で見て判断しない。
  - 測る文字列: 全角文字、半角カナ、幅が曖昧な文字（罫線・`…`・`○`・`①`・ギリシャ文字）、NFD の濁点、絵文字（単独、VS16 付き、ZWJ でつないだもの、国旗、肌の色の修飾）、不正な UTF-8。
  - あわせて、幅がずれる名前の後ろに位置を指定した欄を描き、ずれがどこまで広がるかを撮影する。
- `tuiprobe keys`: キー入力の記録（VU1 の一部）。
  - 案内に従ってキーを押してもらい、受け取ったもの（Unix は生のバイト列、Windows は入力のレコード）を、届いた時刻とともに記録する。
  - 記録するキー: Esc（遅延も測る）、Shift＋英字、Ctrl＋英字、Alt＋英字、Backspace、Delete、矢印、PgUp・PgDn・Home・End、Tab、Shift＋Tab、Enter、F1〜F12、
    Ctrl＋H・I・M・[（Backspace・Tab・Enter・Esc と区別できるか）、IME で確定した日本語、貼り付け。
  - この記録を、`keys` のテストの入力にする（tui §5）。
- どちらも、結果を `docs/probe-results/<端末>-<日付>.json` に書く。各項目の結果には、この節に表をまとめる。
- フェーズ16（§13）で、自作の土台の上に確認用の画面を作り、VU1・VU4・VU5・VU9 を確かめる。

### 12.2 確かめる環境と分担

- Mac: Terminal.app と iTerm2。
  - `width` は Claude が `open -a` で起動し、結果のファイルを読む（入力が要らないため）。
  - `keys` と IME は開発者が行う。computer use では、端末のアプリに文字を打てないため。
- Windows: Parallels Desktop の仮想マシン（Windows 11 の ARM 版）。Windows Terminal と conhost。
  - `width` は Claude が行う。端末は `prlctl exec` で起動し（conhost は `conhost.exe` から直接起動する）、画面は computer use で撮影する。既定の端末の設定は変えない。
  - `keys` と IME は開発者が実物のキーボードで行う。Claude は起動用のファイルを用意する。
    フェーズ12で、computer use で送るキーは当てにならないと分かったため（Esc は computer use の停止のキーなので届かない。文字のキーは Windows 11 の長押しの候補を開き、後のキーを飲み込んだ）。
  - VM では、Mac の Option が Ctrl として届くことがあった（Parallels のキーの対応によると思われる）。
  - 仮想マシンの設定（日本語 IME の追加など）は開発者が行う。
  - 仮想マシンは ARM 版の Windows 11 なので、x64 の PC や Windows 10 の conhost とは違いうる。結果には OS と端末の版を記録する。
- 手順は PROMPTS.md の「仮想マシンでの確認」に書く。

### 12.3 TUI のライブラリを使わない理由（資料の調査。2026-09-26）

次の調査の結果と、依存を増やさない方針（§4）から、ライブラリを使わずに自作する。自作で行き詰まったら、tcell v3 を検討し直す。

- Bubble Tea v2（v2.0.10）: 依存が多い。中国語などの描画の不具合（charmbracelet/bubbletea#1777）が未解決。Elm 式のイベントループが `app` の役割と重なる。
- tview: tcell v2 に留まっている。部品（リスト・入力欄）が自分で状態を持つので、§4 の境界とぶつかる。
- tcell v3（v3.5.0）: 試験用の画面（`SimulationScreen`）が削除された。
- 参考にした事実（確かめたものではない）:
