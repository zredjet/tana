# fsops を Claude Code で作る手順

あなた（開発者）用の手順書です。フェーズごとのプロンプトをコピーして Claude Code に渡してください。
このファイル自体はリポジトリに入れても入れなくても構いません。

---

## 0. 準備（Mac で 1 回だけ）

1. Go を入れる
   ```sh
   brew install go
   go version
   ```
2. Xcode コマンドラインツールを入れる（macOS のごみ箱処理で cgo を使うため）
   ```sh
   xcode-select --install
   ```
3. GitHub CLI を入れてログインする（Claude Code が CI の結果を読むため）
   ```sh
   brew install gh
   gh auth login
   ```
4. GitHub にリポジトリを作る。**公開か非公開か**を決めておく（非公開の場合、macOS の CI は手動・PR 時だけにする。SPEC §19）。
5. リポジトリを clone し、この一式のうち `CLAUDE.md` と `docs/SPEC-fsops.md` を配置してコミット・push する。
6. リポジトリ直下で Claude Code を起動する。
   ```sh
   claude
   ```

---

## 1. 進め方のコツ

- **フェーズの最初はプランモード**にする（Shift+Tab で切り替え）。計画を読んで納得してから実装に進ませる。
- **フェーズが終わったら `/clear`** して会話をリセットしてから次のフェーズへ。CLAUDE.md は毎回自動で読まれるので、前提は失われない。
- Claude Code が「要検証事項（V1〜V10）」の結果を報告してきたら、SPEC §20 に結果を追記させる。
- 迷ったら「§2 の不変条件を破らないか」を基準に判断する。

## 2. フェーズごとのプロンプト

### フェーズ0: 計画の確認（コードは書かない）

```

次の3点を報告してください。
1. SPEC の API 案（§5）とファイル構成案（§4）について、Go の慣習や実装の都合から改善したほうがよい点
2. SPEC の中で矛盾している箇所、または曖昧で実装時に判断が分かれる箇所
3. このあとのフェーズ1〜9の順序や区切りで、変えたほうがよい点
SPEC を変更する提案がある場合は、変更後の文面まで示してください。私が承認してから SPEC を更新してください。
```

承認した変更を SPEC に反映させたら、コミットさせて `/clear`。


## 3. 困ったとき用のプロンプト

### CI の Windows だけ失敗する

```
GitHub Actions の Windows ジョブが失敗しました。gh run view --log-failed でログを確認し、原因を特定して報告してください。
修正の前に、なぜ macOS では通ったのかを説明してください。
Windows 固有の挙動が原因なら、それを再現する最小のテストを先に追加してから直してください。
```

### テストがときどき失敗する

```
<テスト名> が CI でときどき失敗します。gh で直近の失敗ログを集め、原因の候補を挙げてください
（タイミング依存、ウイルス対策ソフトによる一時的なロック、一時フォルダの扱いなど）。
テストにスリープやリトライを足して隠す修正はしないでください。
fsops の実装側で共有違反に短いリトライを入れるべきだと考える場合は、その案と不変条件への影響を示して私に確認してください。
```

### 仕様を変えたい

```
<変えたい内容> のように仕様を変えたいです。
SPEC のどの節に影響するか、§2 の不変条件と衝突しないかを確認し、SPEC の変更案とテストへの影響を示してください。
私が承認するまで実装しないでください。
```

### 不変条件の監査（いつでも）

```
現在の internal/fsops のコードを、docs/SPEC-fsops.md §2 の不変条件 I1〜I7 の観点だけで見直してください。
各不変条件について、それを破りうるコード経路と、それを防いでいるテストを対応づけて示し、
テストで守られていない経路があれば列挙してください。修正はまだしないでください。
```

## 4. CI 以外での確認（リリース前）

CI では確かめられないものがあります（SPEC §20 の V9 など）。

- 日本語ロケールの Windows での動作
- OneDrive の同期フォルダ（未ダウンロードのファイル）
- ネットワークドライブ、USB メモリ

UTM などの仮想マシンの Windows、または実際に使う Windows PC で、フェーズ9の `fsopsctl` を使って確認してください。
Windows 用のバイナリは Mac 上で作れます。

```sh
GOOS=windows GOARCH=amd64 go build -o fsopsctl.exe ./cmd/fsopsctl   # 一般的な PC 用
GOOS=windows GOARCH=arm64 go build -o fsopsctl.exe ./cmd/fsopsctl   # Apple Silicon の Mac 上の Windows 用
```
