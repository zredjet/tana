# tana 仕様書（TUI の土台）

たたき台（2026-09-26）。フェーズ12の実測（`docs/probe-results`）を反映（2026-09-26）。

ファイラー本体の仕様は `docs/SPEC-filer.md`（本書では「filer §n」と書く）、ファイル操作の仕様は `docs/SPEC-fsops.md`（「fsops §n」）に書く。

---

## 1. 目的と範囲

tana は TUI のライブラリを使わず、端末の入出力を自作する（filer §4、filer §12.3）。本書は、その土台となるパッケージの仕様である。

目的:

- 依存を、標準ライブラリ・`golang.org/x/sys`・`golang.org/x/text` だけにする。
- 文字の幅・キーの解釈・描画を自分で持ち、ライブラリの計算ではなく、端末で実測した結果に合わせる。

方針:

- 役割ごとに小さなパッケージに分け、それぞれを単独でテストして完成度を上げてから組み合わせる。
- OS に依存する部分（`term`）と、純粋な計算の部分（`textwidth`・`keys`・`screen`・`lineedit`）を分ける。
  純粋な部分は、バイト列と値だけを扱う。端末がなくても、CI で網羅的にテストできる。
- 各パッケージの API には、ファイラー固有の概念（ペイン、ファイル）を入れない。

扱わないもの（v0.1）:

- マウス
- Kitty キーボードプロトコルなどの拡張されたキーの報告
- 256 色・24 ビット色（16 色と端末の既定の色だけを使う）
- サスペンド（Ctrl+Z でシェルに戻る）
- 部品（リスト、ダイアログ）。これらはファイラーの `tui` が持つ
- VT のシーケンスを解釈しない古いコンソール（Windows 10 1511 より前）

## 2. 不変条件

土台が守る約束。ファイラーの U1〜U6（filer §2）を、土台の側から支える。

- **T1 端末を必ず元に戻す**
  正常終了・エラー・panic・シグナル（Windows のコンソールを閉じる通知を含む）のどれでも、開始前の状態に戻す。
  戻すもの: raw モード、代替画面、カーソルの表示、自動改行、貼り付けのモード、Windows のコンソールモード。
  戻す処理は、何度呼んでも、どの goroutine から呼んでも安全にする。
  ただし、強制終了（SIGKILL、タスクの終了）と、作業用の goroutine で回収されなかった panic では戻せない。
  そのため、ファイラーは作業用の goroutine の panic を回収する（filer §10）。

- **T2 表示する文字列から制御シーケンスを出力しない**
  端末に書く制御シーケンスは、`screen` と `term` が作るものだけとする。
  描画する文字列に、端末に出してはいけない文字（`textwidth` が判定する。§4）が含まれていれば、`screen` が `?` に置き換える。
  filer §9.3 の置き換えが漏れた場合の、二重の防御である。

- **T3 入力を失わず、作らない**
  `keys` は、受け取った入力をすべて、いずれかのイベントに対応させる。解釈できない入力は「解釈できない入力」のイベントにする。
  各イベントは元の入力を持ち、イベントの元の入力を順につなぐと、受け取った入力と一致する。
  存在しない入力からイベントを作らない。
  Windows の入力のレコードをバイト列に変える `term` も、この約束を守る（§8）。
  - 文字を持つレコードは、必ずバイト列に対応させる。キーを押したレコードの文字に加えて、conhost が Alt＋テンキーの並びの最後に送る、Alt を離したレコードの文字も含む（フェーズ12の実測）。
  - 文字を持たないレコード（キーを離したレコード、VT の入力モードで conhost が送る Shift・Ctrl のレコードなど）は、入力を表さないので捨ててよい。

- **T4 幅の判断を 1 か所にする**
  書記素クラスタの区切りと表示幅は、`textwidth` だけが決める。`screen`・`lineedit`・ファイラーの `textfmt` は、すべて `textwidth` を使う。

- **T5 領域の外に描かない**
  領域（ペインなどの矩形）に描いた内容が、その外のセルを変えない。
  幅 2 以上の書記素クラスタが領域の右端にかかるときは、そのクラスタを置かずに空白で埋める。

- **T6 画面は格子と一致する**
  描画の後、端末の表示は `screen` の格子と一致する。ただし、端末の幅の計算が `textwidth` と同じ場合に限る。
  幅の計算が合わない端末でも、ずれは次の行・次の領域・次の位置の指定で止まる（§6）。
  ただし Terminal.app は、複数の符号位置からなる書記素クラスタ（ZWJ でつないだ絵文字、肌の色の修飾、国旗など）がある行を、
  格子ではなく文字の並びとして描く。そのため、位置を指定し直しても、その行の後ろの表示がずれる（フェーズ12の実測）。
  そこで、端末によって幅や描き方が割れる書記素クラスタは、そのまま出力せず、表示を簡略な形に置き換える（§4）。

## 3. 構成と依存

```
internal/term/       OS ごとの端末の入出力（§8）
internal/textwidth/  書記素クラスタと表示幅、端末に出してはいけない文字の判定（§4）
internal/keys/       入力をイベントに変える（§5）
internal/screen/     セルの格子、領域、差分の出力（§6）
internal/lineedit/   1 行の入力欄の編集（§7）
```

依存の向き:

- `textwidth`・`keys` は、標準ライブラリだけを使う。
- `screen`・`lineedit` は、`textwidth` を使う。
- `term` は `golang.org/x/sys` を使う。OS ごとのコードは `term` に閉じ、ファイル名のサフィックスとビルドタグで分ける（CLAUDE.md の fsops の実装ルールと同じ）。
  x/sys にない Windows の関数（`ReadConsoleInputW` など）は、fsops と同じく `LazyDLL` で呼ぶ。
- 5 つのパッケージは、互いのうち上に挙げた以外のものと、それより上位のもの（`tui`・`app`・`fsops` など）を import しない。
- この依存の向きを `deps_test.go`（fsops と同じ方式）で確かめる。

置き場所:

- 5 つのパッケージは `internal/` に置く。ほかのプロジェクトから使う必要が出たら、`internal/` の外へ出す（fsops §4 と同じ）。

## 4. textwidth

役割:

- 文字列を書記素クラスタ（Unicode の UAX #29 の extended grapheme cluster）に分ける。
- 書記素クラスタごとに、次の分類と、表示する形と、その表示幅を返す。表示幅は、表示する形の幅とする。
  表示幅は 1 以上で、上限はない（幅の和の規則で 3 以上になるクラスタがある。例: デーヴァナーガリーの क्षि は 3）。

  | 分類 | 表示する形 |
  |---|---|
  | 通常の文字 | そのまま |
  | 端末に出してはいけない文字（下の一覧） | `?` |
  | 不正な UTF-8 のバイト | `?`（1 バイトずつ） |
  | 見えない書記素クラスタ（下の一覧） | `?` |
  | 不安定な書記素クラスタ（下の一覧） | 簡略な形（下の一覧） |

- 表示する形を使うのは表示だけ。元のバイト列は変えない（filer U4）。`screen`・`lineedit`・`textfmt` は、描くときにこの形を使う。
- 幅が端末によって違いうる書記素クラスタに印を付ける。`screen` は、その後で位置を指定し直す（§6）。対象は次のもの。
  - 幅が曖昧な文字（East Asian Width が A）。conhost は多くを 2 桁にする
  - Unicode 16.0 より新しい版で加わった絵文字。16.0 までの絵文字（🫨・🪾 など）は、主な 3 端末で 2 桁だった。
    17.0 の絵文字は Windows Terminal で 1 桁、18.0 の絵文字は 4 端末とも 1 桁だった（端末の表が追いついていない。フェーズ13の実測）
  - 幅が 3 以上の書記素クラスタ。デーヴァナーガリーの क्षि は Terminal.app・iTerm2 で 3、Windows Terminal で 2、
    ハングル字母 L＋L は Terminal.app で 4、iTerm2・Windows Terminal で 2 だった（フェーズ13の実測）

端末に出してはいけない文字（filer §9.3 の置き換えの対象と同じ。定義はここだけに置く）:

- 制御文字（U+0000〜U+001F、U+007F〜U+009F）
- 双方向の制御文字（U+202A〜U+202E、U+2066〜U+2069）と、方向の印（U+200E、U+200F、U+061C）
- 行区切り・段落区切り（U+2028、U+2029）
- 不正な UTF-8 のバイト（1 バイトずつ、独立した書記素クラスタにする）

見えない書記素クラスタ（幅が 0 桁か 1 桁かで端末が割れる。名前の偽装にも使われる）:

- 既定で無視される文字（Default_Ignorable_Code_Point。ZWSP・ZWJ・WJ・BOM・SHY・CGJ など）だけからなるもの
- 結合文字（一般カテゴリが Mn・Me）で始まるもの（文字列の先頭にある結合文字など）
- そのほか、下の幅の規則で幅が 0 になるもの（前に初声のない、単独のハングルの中声字母など）

不安定な書記素クラスタ（端末によって幅と描き方が割れる。フェーズ12の実測。filer §12.5）と、その表示する形:

| 書記素クラスタ | 表示する形 |
|---|---|
| ZWJ でつないだ絵文字の並び | 最初の絵文字（その後の修飾・異体字セレクタを除く） |
| 肌の色の修飾（U+1F3FB〜U+1F3FF）が付いた絵文字 | 修飾を除いた絵文字 |
| VS16（U+FE0F）が付いたもの | VS16 を除いた形 |
| キーキャップ（U+20E3 で終わる並び） | 最初の文字 |
| タグの並び（U+E0020〜U+E007F を含むもの） | 最初の絵文字 |
| 地域指示記号（U+1F1E6〜U+1F1FF。対でも単独でも） | 1 つにつき `?` |

簡略な形にすると、幅は主な 3 端末（Terminal.app・iTerm2・Windows Terminal）で一致する。例: 👨‍👩‍👧 → 👨（2 桁）、❤️ → ❤（1 桁）、#️⃣ → #（1 桁）。

表:

- 固定した版の Unicode のデータ（`GraphemeBreakProperty.txt`・`emoji-data.txt`・`EastAsianWidth.txt`・`DerivedGeneralCategory.txt`・`DerivedCoreProperties.txt`・`DerivedAge.txt` など）をリポジトリに置く。
  - `go generate` で Go の表を作り、生成した表をコミットする。
  - 版はフェーズ13の時点の最新のものとし、doc.go に書く。
- `x/text/width` は使わない。すべての表の Unicode の版をそろえるため。

幅の規則（フェーズ12の実測で決めた。filer §12.5）:

- 書記素クラスタの幅は、クラスタの中の各符号位置の幅の和とする。
  - East Asian Width が W・F の文字は 2
  - 結合文字（一般カテゴリが Mn・Me）、異体字セレクタ、既定で無視される文字（ZWJ など）、ハングルの中声・終声の字母（U+1160〜U+11FF、U+D7B0〜U+D7FF）は 0
  - それ以外は 1（幅が曖昧な文字、スペーシングマーク（Mc）、半角の濁点・半濁点（U+FF9E・U+FF9F）を含む）
- 例: NFD の「が」（か＋U+3099）は 2、半角の「ｶﾞ」は 2、IVS の付いた「葛」は 2、タイ文字の「กำ」は 2。どれも 4 端末で実測した値と同じ。
  「先頭の文字で決める」規則では、「ｶﾞ」と「กำ」が 1 になり、実測と合わない。
- 幅が曖昧な文字（East Asian Width が A）は 1 とする。主な 3 端末の既定の設定で 1 だった（filer の VU2）。変更する設定は設けない。
- 絵文字の並びは、簡略な形にしてから数える（上の「不安定な書記素クラスタ」）。
- 幅が 3 以上になる書記素クラスタ（デーヴァナーガリーの क्षि、ハングル字母 L＋L など）は、端末によって幅が違う。
  日本語のファイル名ではまれなので、置き換えずに和の幅を使い、「幅が端末によって違いうる」印を付ける（上の役割）。
- Unicode 16.0 より新しい絵文字は、Unicode の表のとおり 2 とし、「幅が端末によって違いうる」印を付ける。

テスト:

- Unicode の `GraphemeBreakTest.txt` のすべての行で、分け方が一致すること。
- フェーズ12の実測の結果（`docs/probe-results`）を期待値の表にすること。
  - 表示する形の幅が、主な 3 端末の実測と一致すること。
  - 置き換える書記素クラスタは、置き換える前の形の幅が端末で割れていたこと（置き換える理由）も表に残す。
- ファジング:
  - 任意のバイト列で panic しない。
  - 書記素クラスタをつなぐと元のバイト列に戻る。
  - 表示幅は 1 以上で、表示する形を幅の規則で数えた値と一致する。
  - 表示する形は、端末に出してはいけない文字・見えない書記素クラスタ・不安定な書記素クラスタを含まない。

## 5. keys

役割:

- 端末からの入力（バイト列）を、イベントの列に変える。
  - Unix: 端末から読んだバイト列
  - Windows: VT の入力モードで読んだ入力のレコードを、`term` がバイト列に変えたもの（§8。VT2 の結果）
  - フェーズ12の実測では、VT の入力モードの Windows Terminal と conhost は、Terminal.app・iTerm2 と同じシーケンスを送った。
- イベントの種類:
  - キー（種類と修飾キー。文字のキーは文字を持つ）
  - 貼り付け（文字列）
  - カーソル位置の報告
  - 解釈できない入力
  - 大きさの変更は `term` が知らせる（§8）。`keys` は扱わない。
- 純粋な状態機械とし、時刻は呼び出し側から渡す。こうすると、Esc の待ち時間をテストで操作できる。
  - Esc（`0x1b`）を受け取った後、待ち時間の間に続きが来なければ、Esc のキーとして確定する。
  - 待ち時間は 50 ミリ秒とする（フェーズ12の実測）。
    - 4 端末とも、シーケンスが読み取りの途中で分かれて届いたことはなかった。
    - 人が Esc の後に続けて x を押した間隔は、最短で 282 ミリ秒だった。
  - 次にいつ確定の処理を呼べばよいかを、呼び出し側に返す。

解釈:

- 対応するシーケンスは、フェーズ12で記録した各端末のもの（`docs/probe-results`）とする。
- 未知のシーケンスは、解釈できない入力として元のバイト列ごと返す。呼び出し側がログに残せるようにする。
- カーソル位置の報告（`ESC[行;桁R`）は、修飾キー付きの F3（`ESC[1;2R` など）と同じ形になる。
  そのため、呼び出し側が問い合わせを出して応答を待っている間だけ、カーソル位置の報告として解釈する。
- 同じバイトで届くキー（フェーズ12の実測）:
  - Tab と Ctrl＋I（`0x09`）、Enter と Ctrl＋M（`0x0D`）、Esc と Ctrl＋[（`0x1B`）は区別できない。`0x09`・`0x0D`・`0x1B` は Tab・Enter・Esc とする。
  - Backspace（`0x7F`）と Ctrl＋H（`0x08`）は区別できる。
  - Mac の Option は、既定では Alt ではなく文字を送る（Option＋A で「å」）。Windows Terminal の Alt＋A は `ESC a` で届く（conhost は未確認）。
- 貼り付け:
  - bracketed paste（`ESC[200~` から `ESC[201~` まで）を、貼り付けのイベントにする。
  - 貼り付けの中身をキーとして解釈しない（filer U2）。
  - 貼り付けの中の改行は CR（`0x0D`）で届く（フェーズ12の実測）。
  - bracketed paste は 4 端末とも使える（VT6）。Windows で VT の入力モードを使わないと、貼り付けはキーの列として届き、区別できない。
  - 終わりの印（`ESC[201~`）が届かないとき（フェーズ14で決めた）:
    - 最後の入力から 1 秒たったら、そこまでを貼り付けのイベントにする。その後に届いたものも、終わりの印までは貼り付けとして扱い、キーとして解釈しない（filer U2）。
    - 貼り付けのイベントにした後、さらに 1 秒なにも届かなければ、貼り付けを終える。次の入力はキーとして扱う（終わりの印を送らない端末でも操作できなくならないように）。

テスト:

- フェーズ12の記録を入力にした、端末ごとの表のテスト。
- ファジング:
  - 任意の入力で panic しない。
  - T3 を満たす（イベントの元の入力をつなぐと、受け取った入力と一致する）。
  - 有限の回数の確定の処理で、保留中の入力がなくなる。
  - 区切りに依存しない: 同じバイト列を任意の位置で分けて渡しても、分けた間隔が待ち時間を超えない限り、同じイベントの列になる。

## 6. screen

役割:

- セルの格子を持つ。各セルは、書記素クラスタ、幅、属性（色、太字、暗く、反転、下線）を持つ。
  幅 N（2 以上）の書記素クラスタは、先頭のセルと、N−1 個の「続き」のセルで持つ。
- 領域（矩形）に描く。領域に描く操作は T5 を守る。
  - 文字列を置く（はみ出した分は切る。書記素クラスタの途中では切らない）
  - 塗る
- 書記素クラスタは、`textwidth` が返す表示する形で置く。端末に出してはいけない文字と見えない書記素クラスタは `?`、不安定な書記素クラスタは簡略な形になる（T2・T6。§4）。
- 本物のカーソルの位置と、表示・非表示を持つ。IME の変換中の文字は、このカーソルの位置に出る（filer の VU4）。

出力:

- 前回の出力からの差分を、エスケープシーケンス（カーソルの移動、SGR、文字）にして `io.Writer` に書く。
- 次の位置では、カーソルの位置を指定し直す（T6）。
  - 行の始め
  - 領域の始め
  - 幅が端末によって違いうる書記素クラスタの後（`textwidth` が印を付けたもの）
- 描き終えたら、カーソルを本物のカーソルの位置に置き、表示・非表示を設定する。
- 端末の大きさが変わったときなどに、全体を描き直せるようにする。
- `NO_COLOR` のときは色を捨て、太字・暗く・反転・下線は残す（filer §9.5）。
- 自動改行（DECAWM）は切った状態で使う。切るのと戻すのは `term` が行う（§8）。
- 同期出力（mode 2026）を使うかは、実測の結果（VT5）で決める。フェーズ12の下調べは §9 の VT5 に書く。

テスト:

- テスト用の小さな端末エミュレータを `screen` の下に作る。
  - 解釈するのは、`screen` が出力するシーケンス（カーソルの移動、SGR、消去、文字）だけ。
  - 幅は `textwidth` で数える。
- 性質のテスト（ファジング）:
  - 任意の描画の操作と出力を繰り返した後、エミュレータの画面が格子と一致する（T6）。
  - 領域に描いても、領域の外のセルが変わらない（T5）。
  - 出力に含まれる制御文字は、`screen` が作るシーケンスのものだけ（T2）。
- 幅の計算が合わない端末の模擬:
  - エミュレータの幅の計算を一部の文字で変える（例: 幅が曖昧な文字を 2 桁にする）。
  - ずれが、その行のその領域の中で止まることを確かめる（T6）。

## 7. lineedit

役割:

- 1 行の入力欄の状態と、編集の操作を持つ。
  - 状態: 文字列（元のバイト列のまま）と、カーソルの位置（書記素クラスタの境界）
  - 操作: 文字列の挿入、前後の書記素クラスタの削除、カーソルの移動（左右、先頭、末尾）
- 挿入する文字列から、改行（CR と LF）と、端末に出してはいけない文字は取り除く（貼り付けで改行が入らないようにするため）。
  貼り付けの中の改行は CR で届く（§5）。
- 表示の範囲を決める。欄の幅に合わせて横に動かし、カーソルが常に見えるようにする。
  表示用の置き換え（`?` など）は描画のときに行い、状態の文字列は変えない（filer U4）。
- 変更したかどうかを、変更する操作があったかどうかで返す。文字列の比較で判断しない（filer §8.7）。

テスト:

- 表のテスト。NFD の名前、絵文字、不正な UTF-8 のバイトを含む名前を使う。
- ファジング（任意の操作の列）:
  - カーソルは常に書記素クラスタの境界にある。
  - 変更する操作をしなければ、文字列は元のバイト列のまま。
  - 文字列は、元の文字列と挿入した文字列の部分からだけできている。

## 8. term

役割:

- 開始と終了:
  - 開始時に、次の状態を記録して変える。
    - raw モード
    - 代替画面
    - カーソルを隠す
    - 自動改行を切る
    - bracketed paste（VT6 の結果、4 端末とも使える）
    - Windows のコンソールモード
      - 入力: Ctrl+C をキーとして受け取る（`ENABLE_PROCESSED_INPUT` を外す）、行の入力とエコーをやめる、簡易編集モードを切る、大きさの変更のイベントを受け取る、
        VT の入力モードを付ける（`ENABLE_VIRTUAL_TERMINAL_INPUT`。VT2 の結果）
      - 出力: VT のシーケンスを解釈させる（`ENABLE_VIRTUAL_TERMINAL_PROCESSING`）。LF で行の始めに戻さない（`DISABLE_NEWLINE_AUTO_RETURN`。Unix の raw モードと同じにする）
  - 終了時に、すべてを開始前の状態に戻す（T1）。
- 出力:
  - Unix は端末の fd に書く。
  - Windows は、UTF-8 を UTF-16 に変えて `WriteConsoleW` で書く（VT1 の結果）。コードページは変えない。
    書き込みの境界で切れた UTF-8 の文字は、次の書き込みまで持っておく。
- 入力: 別の goroutine で読み、`keys` に渡すバイト列にして送る。
  - Unix: 端末の fd から読む。
  - Windows: VT の入力モードで `ReadConsoleInputW` で読み、レコードをバイト列に変える（T3）。
    - キーを押したレコードの文字（UTF-16）を UTF-8 にする。サロゲートの対は、2 つのレコードにまたがっても組み立てる。対にならない半分は U+FFFD にする。
    - conhost が Alt＋テンキーの並びの最後に送る、Alt を離したレコードの文字も含める（BMP の外の文字を貼り付けたとき）。
    - IME で確定した文字は、仮想キーコードが 0 のレコードに文字として届く。
    - 文字を持たないレコード（キーを離したレコード、conhost が送る Shift・Ctrl のレコード）は捨てる。
    - 大きさの変更のレコードは、大きさの変更として知らせる。起動した直後にも届く。
  - 終了時に、読み取りの goroutine を止める（フェーズ12で実装した）。
    - Unix: 端末とパイプを select で待ち、パイプに書いて起こす。macOS の poll は端末のデバイスに使えない。
    - Windows: 入力のハンドルとイベントを `WaitForMultipleObjects` で待ち、イベントを設定して起こす。
- 大きさ:
  - Unix: `TIOCGWINSZ` で得て、SIGWINCH で知る。
  - Windows: `GetConsoleScreenBufferInfo` で得て、大きさの変更のイベントで知る（VT4）。
- シグナル: SIGINT・SIGTERM・SIGHUP を受けてイベントにする。
  - Windows では、`os/signal` がコンソールを閉じる通知（`CTRL_CLOSE_EVENT`）なども SIGTERM として届ける。その後、約 5 秒で OS に終了させられる。
- カーソル位置の問い合わせ（`ESC[6n`）を出す。応答は `keys` がカーソル位置の報告にする（§5）。フェーズ12の幅の実測で使う。
  Windows では、VT の入力モードでなければ応答が届かない（フェーズ12の実測）。
- conhost では、このモードで Ctrl＋V が貼り付けにならず、キー（`0x16`）として届く。貼り付けは右クリックのメニューで行う（filer §15）。

テスト:

- CI の中で、疑似端末を作って `term` を動かす（VT3）。
  - Unix: `/dev/ptmx`
  - Windows: 疑似コンソール（`CreatePseudoConsole`）
- 確かめること:
  - 開始して終了した後、端末の設定が開始前と同じ
  - 書いた入力が届く
  - 大きさの変更が届く
- 実際の端末での確認は、filer §12 の手動の確認で行う。

## 9. 要検証事項

filer §12 と同じく、推測で決めずに試し、結果をこの節に追記する。

- **VT1** Windows の出力の方法。
  - `WriteConsoleW`（UTF-16）で VT のシーケンスと日本語を書いて、Windows Terminal と conhost で正しく表示されるか。
  - コードページを変えずに済むか。
  - 結果（フェーズ12、2026-09-26。Windows 11 ARM、コードページ 932）: **`WriteConsoleW` にする。コードページは変えずに済む。**

    | 方法 | Windows Terminal | conhost |
    |---|---|---|
    | `WriteConsoleW`（UTF-16） | 正しく表示される。幅の実測も同じ | 正しく表示される |
    | コードページを UTF-8 にして `WriteFile` | `WriteConsoleW` と同じ（不正な UTF-8 のバイトの数え方だけ違う） | （測っていない） |
    | コードページを変えずに `WriteFile` | 日本語が化け、制御シーケンスも壊れる（`[3;1H` がそのまま出た） | （測っていない） |
- **VT2** Windows の入力の方法。`ReadConsoleInputW` で、VT の入力モード（`ENABLE_VIRTUAL_TERMINAL_INPUT`）を付けた場合と付けない場合で、次のものの届き方がどう違うか。
  - 矢印キー、F キー、修飾キー
  - Esc
  - IME で確定した文字
  - 貼り付け
  - 結果（フェーズ12）: **VT の入力モードを使う。** 記録は `docs/probe-results`、表は filer §12.5。

    | | VT の入力モードあり | なし |
    |---|---|---|
    | 矢印・F キーなど | Terminal.app・iTerm2 と同じシーケンス（`ESC[A`、`ESC OP` など）が、1 回の読み取りで届く | 仮想キーコードだけのレコード（文字なし） |
    | Esc | `0x1B` | `VK_ESCAPE`（文字 `0x1B`） |
    | Ctrl＋I・M・[ | Tab・Enter・Esc と同じバイト | 仮想キーコードで区別できる |
    | Alt＋A | `ESC a`（Windows Terminal。conhost は未確認） | Alt のフラグ付きの `a` |
    | 修飾キーだけ | Windows Terminal は送らない。conhost は文字のない Shift・Ctrl のレコードを送る | 文字のないレコード |
    | IME で確定した文字 | 仮想キーコード 0 のレコードに文字 | 同じ |
    | 貼り付け | bracketed paste の印が付く | 印が付かない（打鍵と区別できない） |
    | カーソル位置の報告 | 届く | 届かない（width の実測が 3 件で止まった） |

    VT の入力モードにすると、Ctrl＋I・M・[ を区別できなくなるが、Mac の端末と同じなので、割り当てに使わなければ困らない（filer §7）。
- **VT3** CI の疑似端末（macOS・Linux）と疑似コンソール（Windows）の中で、`term` のテストができるか。
- **VT4** Windows Terminal と conhost で、大きさを変えるたびに大きさの変更のイベント（`WINDOW_BUFFER_SIZE_EVENT`）が届くか。
  届かない場合は、入力やタイマーのたびに大きさを調べ直す。
- **VT5** 各端末で、次の機能が使えるか。
  - 同期出力（mode 2026）
  - 代替画面
  - 自動改行を切る設定（DECAWM）
  - カーソルの表示・非表示
  - フェーズ12の下調べ（DECRQM の応答。確定はフェーズ16）:
    - 同期出力: iTerm2・Windows Terminal は対応（応答 2）。conhost は非対応（応答 0）。
    - 代替画面・DECAWM・カーソルの表示: iTerm2・Windows Terminal・conhost は DECRQM に応答した。
    - Terminal.app は DECRQM に応答せず、問い合わせの一部を文字として表示した。Terminal.app には DECRQM を送らない。
- **VT6** bracketed paste が各端末で使えるか。Windows の入力のレコードで、貼り付けがどう届くか。
  - 結果（フェーズ12）:
    - Terminal.app・iTerm2・Windows Terminal（VT の入力モード）・conhost（VT の入力モード）で使える。改行は CR で届く。
    - VT の入力モードでない Windows では、印が付かず、キーのレコードの列として届く。
    - conhost では、このプローブの入力モードで Ctrl＋V が貼り付けにならず、`0x16` がキーとして届く。右クリックのメニューで貼り付けると届く。
    - conhost は、BMP の外の文字（🍣 など）を Alt＋テンキーの並びで送り、文字を Alt を離したレコードに載せる。bracketed paste の印の内側に届く。
